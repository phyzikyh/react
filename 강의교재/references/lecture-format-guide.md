# 강의교재 표준 포맷 가이드

> 모든 주차(`weekNN_lecture.qmd`)가 따르는 **공통 틀**. 시중 프로그래밍 교재처럼 "개념 → 예제 → 직접 해보기 → 확인 문제"가 규칙적으로 반복되는 구조를 규정한다. 내용을 쓰기 전에 이 틀부터 맞춘다.

## 설계 원칙

1. **반복되는 리듬.** 학생이 페이지를 넘길 때마다 같은 순서(설명→예제→미션→문제)가 나와 예측 가능하다.
2. **읽기만 하지 않게.** 개념마다 손으로 하는 **직접 해보기**와 스스로 푸는 **확인 문제**를 끼운다.
3. **예제는 붙여넣기 실행형.** 모든 예제 코드는 `src/App.jsx`에 그대로 붙이면 돌아간다.
4. **스타일은 본문에서 빼기.** 예제 코드는 구조·로직만. 색/여백은 공통 CSS로 미리 제공하고 예제에서 다루지 않는다.
5. **아이콘(이모지) 금지.** 제목·본문에 이모지를 쓰지 않는다. 블록은 글자 라벨로 구분한다.
6. **다른 주차 언급 금지.** 지난주·다음주·"N주차"·"이후에 배운다" 같은 표현을 쓰지 않는다. **해당 주차에서 다루는 개념·문법만**으로 예제와 설명을 구성한다.

---

## A. 주차 문서 전체 뼈대

```text
─ 프론트매터 (title / subtitle / date / number-sections: false)
─ "이번 주로 만들 수 있는 것"         (callout-important, 오프너)
─ "이번 주 배울 개념"                  (배울 개념 3~5개 목록 = 미니 목차)
─ # 1. 개념 A   ← 학습 단위(아래 B 구조 반복)
─ # 2. 개념 B
─ # 3. 개념 C
   …
─ # 이번 주 만들기                     (관통 프로젝트에 이번 주 개념 적용)
```

## B. 학습 단위(Unit) 표준 순서 — 가장 중요

`#` 제목 하나 = 개념 하나. 그 안은 **항상 이 순서**로 쓴다.

```text
# N. 개념 이름

① 개념 설명        2~4문장. "왜 필요한지"를 먼저, "무엇인지"를 다음에.
                   필요하면 표 또는 [그림 N-1].

② 예제 N-1         굵은 라벨 + 붙여넣기 실행형 코드 + "실행 결과"
③ 해설 한 줄        예제에서 짚어야 할 핵심 1~2문장.

(필요 시) 팁 / 용어 / 흔한 실수 박스

④ 직접 해보기       예제를 살짝 바꾸는 미션 1개 (능동)
⑤ 확인 문제         1~2문항, 정답은 접기(collapse)
```

개념이 큰 경우에만 `##`로 하위를 나눈다. 남발하면 목차가 지저분하므로 기본은 `#` 단위 + 본문 블록.

## C. 블록 타입 사전 (Quarto 문법 통일)

| 블록 | 제목(라벨) | Quarto 문법 |
|---|---|---|
| 주차 오프너 | 이번 주로 만들 수 있는 것 | `::: {.callout-important title="이번 주로 만들 수 있는 것"}` |
| 예제 | 예제 N-1: 제목 | **굵은 라벨** + ` ```jsx ` 코드펜스 |
| 실행 결과 | 실행 결과 | 텍스트/스크린샷/`<iframe>` |
| 직접 해보기 | 직접 해보기 | `::: {.callout-tip title="직접 해보기"}` |
| 확인 문제 | 확인 문제 | `::: {.callout-note title="확인 문제"}` + 정답은 중첩 `collapse="true"` |
| 개념 팁 | (내용 제목) | `::: {.callout-note title="..."}` |
| 용어 정리 | 용어 | `::: {.callout-note title="용어"}` |
| 흔한 실수 | 흔한 실수 | `::: {.callout-warning title="흔한 실수"}` |
| 이번 주 만들기 | 이번 주 만들기 | `::: {.callout-important title="이번 주 만들기"}` |

**번호 규칙(주차 N):** 예제 = `예제 N-1, N-2 …` · 그림 = `그림 N-1 …` · 표 = `표 N-1 …`. (하이픈 형식으로 통일)

## E. 작성 규칙 (품질 통일)

- **문장:** 설명은 한 문단 2~4문장. 길면 목록으로.
- **예제 코드:** 한 예제 15줄 이내 권장. 스타일 코드는 넣지 않는다(공통 CSS 사용). 항상 `export default App;`까지 포함해 붙여넣기 실행 가능하게.
- **직접 해보기:** "무엇을·어디에" 한 줄. 정답 코드는 굳이 주지 않는다.
- **확인 문제:** 개념 이해를 묻는 가벼운 1~2문항. 정답은 반드시 `collapse="true"`로 감춘다.
- **범위 제한:** 해당 주차에서 다루지 않는 문법·개념은 예제에 쓰지 않는다. 다른 주차를 언급하지 않는다.
- **핵심 흐름은 라벨로 시각화:** 데이터가 오가는 관계(예: 부모가 값을 주고 자식이 받음)는 말로만 설명하지 말고, 코드에 `// 이름  값` 같은 주석 라벨을 달아 "무엇이 어디로 가는지"를 눈으로 보이게 한다.
- **아이콘 금지:** 제목·본문·표에 이모지를 쓰지 않는다.
- **콜론 부제식 제목 금지:** 제목에 콜론(`:`)으로 부제를 붙이지 않는다. 예: "컴포넌트: 화면을 만드는 부품" → "컴포넌트로 화면 나누기". (프론트매터 `title`의 "N주차: 주제" 형식은 예외로 유지.)
- **접근성:** 이미지 예시는 `alt` 포함. 폼 예시는 `label`+`htmlFor`.
- 한 주차 = 개념 단위 3~5개 + 이번 주 만들기 1개가 표준 분량.
