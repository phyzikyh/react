2.1 HTML 개요

HTML(HyperText Markup Language)은 웹 문서의 내용과 구조, 의미를 표현하는 마크업 언어입니다. 명령을 순서대로 실행하는 프로그래밍 언어라기보다 제목, 문단, 링크, 목록, 표, 이미지와 입력 양식처럼 콘텐츠가 맡은 역할을 표시합니다. 브라우저는 HTML을 읽어 문서 객체 모델(DOM)을 만들고 화면에 표현합니다.

HTML은 정보 구조, CSS는 표현과 배치, JavaScript는 동작을 담당합니다. CSS와 JavaScript를 사용하더라도 명확한 HTML 구조가 먼저 필요합니다. MDN HTML 학습 과정은 HTML을 콘텐츠의 의미와 구조를 정의하는 기술로 설명합니다.

노트HTML 요소를 선택하는 기준

태그의 모양을 암기하는 데 그치지 말고 “이 콘텐츠는 어떤 역할을 하는가?”를 먼저 판단합니다. 역할에 맞는 요소를 선택하면 접근성, 검색, 유지보수와 CSS 작업이 함께 쉬워집니다.

2.2 HTML 문서 기본 구조

<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <meta name="description" content="문서를 설명하는 짧은 문장" />
    <title>HTML 문서</title>
  </head>
  <body>
    <h1>문서의 대표 제목</h1>
    <p>브라우저에 표시할 본문입니다.</p>
  </body>
</html>

<!doctype html>은 현대 HTML 표준으로 문서를 해석하도록 알립니다. html은 문서 전체를 감싸며 lang="ko"는 주 언어가 한국어임을 나타냅니다. 이 정보는 화면 낭독기, 번역 도구와 검색엔진에서 사용됩니다.

head에는 본문이 아니라 문서 정보가 들어갑니다. meta charset은 문자 인코딩, viewport는 모바일 화면의 너비, description은 문서 요약을 제공합니다. title은 브라우저 탭, 방문 기록과 즐겨찾기에 나타나는 제목입니다. body에는 사용자가 읽고 조작할 콘텐츠가 들어갑니다.

head에서 사용하는 주요 요소는 다음과 같습니다.

  • <meta>: 문자 인코딩, viewport, 문서 설명 등의 메타데이터
  • <title>: 문서 제목
  • <link>: 외부 CSS, 아이콘 등 외부 자원과의 관계
  • <style>: 현재 문서에 적용할 CSS
  • <script>: JavaScript 파일 연결 또는 스크립트
  • <base>: 상대 URL이 사용할 기준 URL. 모든 상대 경로에 영향을 주므로 신중하게 사용

2.3 요소, 태그와 속성

<p class="summary">HTML 요소의 구조를 살펴봅니다.</p>

태그 이름은 p, 속성 이름은 class, 속성값은 summary, 내용은 “HTML 요소의 구조를 살펴봅니다.”입니다. <p>는 시작 태그, </p>는 종료 태그이며 전체를 하나의 요소라고 합니다.

속성은 시작 태그 안에 이름="값"으로 작성해 추가 정보나 동작을 제공합니다.

<a href="https://developer.mozilla.org/ko/">MDN 방문하기</a>
<img
  src="https://images.unsplash.com/photo-1498050108023-c5249f4df085?w=600"
  alt="노트북 화면에 코드 편집기가 열린 개발 작업 공간"
/>

태그와 속성 이름은 소문자로, 속성값은 따옴표로 작성하는 습관을 권장합니다. img, br, hr, meta, link, input처럼 내용과 종료 태그가 없는 요소를 빈 요소(void element)라고 합니다. HTML에서는 <img>와 <img />가 모두 허용되지만 프로젝트 안에서는 형식을 통일합니다.

주석

<!-- 프로젝트 목록은 이후에 갱신한다. -->

주석은 화면에 출력되지 않는 설명입니다. 코드의 의도와 임시 작업을 기록할 수 있지만 페이지 소스에서 노출되므로 비밀번호, 개인정보와 내부 주소를 적으면 안 됩니다.

2.4 HTML 문서 작성 규칙

공백과 줄바꿈

일반 텍스트에서 연속된 공백, 탭과 줄바꿈은 하나의 공백으로 합쳐집니다.

<p>
  공백을        여러 번 입력하고
  줄을 바꾸어도 하나의 공백으로 정리됩니다.
</p>
<p>
  공백을 &nbsp;&nbsp;&nbsp; 여러 번 입력하고
  줄을 바꾸어도 하나의 공백으로 정리됩니다.
</p>

간격을 만들려고 공백 문자나 <br>을 반복하지 않습니다. 문단은 p, 목록은 ul이나 ol, 간격과 배치는 CSS를 사용합니다. 입력한 공백과 줄바꿈을 보존해야 하는 코드나 ASCII 도형에는 pre를 사용합니다.

중첩과 들여쓰기

<!-- 올바른 중첩 -->
<p><strong>중요한 내용</strong>을 확인하세요.</p>

<!-- 잘못된 중첩 -->
<p><strong>중요한 내용</p></strong>

요소의 시작과 종료 순서가 교차하면 안 됩니다. 부모 안의 자식 요소를 일정하게 들여쓰면 포함 관계를 쉽게 파악할 수 있습니다. 브라우저가 잘못된 코드를 보정해 화면을 보여주더라도 결과가 의도와 다를 수 있으므로 문법 오류를 고칩니다.

2.5 텍스트 요소

제목

<h1>웹 개발 포트폴리오</h1>
<h2>소개</h2>
<h3>관심 분야</h3>
<h2>프로젝트</h2>
<h3>일정 관리 애플리케이션</h3>

제목은 h1부터 h6까지 여섯 단계입니다. 글자 크기를 위해 선택하지 말고 h1은 문서 대표 주제, h2는 주요 구획, h3은 하위 구획처럼 논리적 계층을 만듭니다. 시각적 크기는 CSS로 조정합니다.

문단, 줄바꿈, 미리 정의된 형식

<p>HTML은 웹 문서의 구조와 의미를 표현합니다.</p>
<p>CSS는 문서의 표현과 배치를 담당합니다.</p>

<address>
  경기도 부천시 경인로 590<br />
  유한대학교
</address>

<pre><code>function hello() {
  console.log("Hello");
}</code></pre>

p는 문단, br은 주소나 시처럼 한 문단 안에서 필요한 줄바꿈, pre는 공백과 줄바꿈을 작성한 형태대로 보존합니다. 문단 사이 간격을 위해 br을 반복하지 않습니다.

주제 전환

hr은 단순 장식선이 아니라 문단 수준의 주제 전환을 나타냅니다.

<p>여기까지는 학습 과정입니다.</p>
<hr />
<p>이제 프로젝트 결과를 소개합니다.</p>

2.6 텍스트 서식과 의미

<p><strong>제출 기한</strong>을 반드시 확인하세요.</p>
<p>파일 이름은 <em>영문 소문자</em>를 권장합니다.</p>
<p>HTML 요소는 <code>&lt;p&gt;</code>처럼 작성합니다.</p>
<p>가격이 <del>30,000원</del>에서 <ins>25,000원</ins>으로 바뀌었습니다.</p>
<p>검색어 <mark>React</mark>가 포함된 부분입니다.</p>
<p>물의 화학식은 H<sub>2</sub>O이고, 2<sup>10</sup>은 1024입니다.</p>
<p><small>이 문장은 보조 정보입니다.</small></p>
  • strong: 강한 중요성이나 긴급성
  • em: 문장 안에서 강조되는 어조
  • code: 코드, 파일 이름, 명령
  • del, ins: 삭제 및 추가된 내용
  • mark: 현재 문맥과 관련되어 표시된 부분
  • sub, sup: 아래 첨자와 위 첨자
  • small: 저작권 문구 등 보조 정보

b는 특별한 중요성 없이 주의를 끌 텍스트, i는 다른 목소리나 전문 용어처럼 일반 문장과 구별되는 텍스트에 사용할 수 있습니다. 단순히 굵거나 기울여 보이게 하려면 CSS를 사용합니다.

<p><b>새 기능</b>: 프로젝트 검색이 추가되었습니다.</p>
<p><i lang="en">component</i>는 UI를 구성하는 단위입니다.</p>

2.7 인용, 약어와 연락처

<p>MDN은 HTML을 <q>웹의 가장 기본적인 구성 요소</q>라고 설명합니다.</p>

<blockquote cite="https://developer.mozilla.org/en-US/docs/Web/HTML">
  <p>HTML은 웹 콘텐츠의 의미와 구조를 정의하는 마크업 언어입니다.</p>
</blockquote>

<p>참고 문헌: <cite>HTML Living Standard</cite></p>
<p><abbr title="HyperText Markup Language">HTML</abbr>은 마크업 언어입니다.</p>

<address>
  작성자: 홍길동<br />
  <a href="mailto:student@example.com">student@example.com</a>
</address>

짧은 인용은 q, 독립된 긴 인용은 blockquote로 나타냅니다. cite 요소는 책, 논문, 영화 같은 창작물의 제목입니다. abbr은 약어이며 처음 등장할 때 title로 전체 의미를 제공할 수 있습니다. address는 가장 가까운 article이나 문서 작성자의 연락처입니다.

2.8 링크

<a href="https://developer.mozilla.org/">MDN Web Docs</a>
<a href="mailto:student@example.com">이메일 보내기</a>
<a href="tel:+821012345678">전화 걸기</a>

a는 다른 문서, 파일, 이메일, 전화번호 또는 같은 문서 위치로 이동하는 링크입니다. 같은 문서 안에서는 대상에 고유한 id를 주고 #id로 연결합니다.

<nav aria-label="페이지 목차">
  <a href="#about">소개</a>
  <a href="#projects">프로젝트</a>
</nav>
<section id="about"><h2>소개</h2></section>
<section id="projects"><h2>프로젝트</h2></section>

target="_blank"는 새 탭이나 창, _self는 현재 문맥, _parent와 _top은 iframe에서 부모와 최상위 문맥을 대상으로 합니다. 새 탭이 꼭 필요할 때는 동작을 알리고 외부 링크에 rel="noopener noreferrer"를 적용할 수 있습니다.

<a href="https://github.com/example" target="_blank" rel="noopener noreferrer">
  GitHub 프로필(새 탭)
</a>

2.9 목록

순서 없는 목록

<ul class="square-list">
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

<ul class="circle-list">
  <li>HTML</li>
  <li>CSS</li>
  <li>JavaScript</li>
</ul>

순서가 중요하지 않은 항목은 ul, 각 항목은 li입니다. 원, 사각형 등 목록 기호는 HTML 속성보다 CSS list-style-type으로 표현합니다. 다음 CSS는 바로 위 HTML의 두 class에 각각 적용됩니다.

.square-list { list-style-type: square; }
.circle-list { list-style-type: circle; }

순서 있는 목록

<ol>
  <li>폴더를 만든다.</li>
  <li>index.html을 만든다.</li>
  <li>브라우저에서 확인한다.</li>
</ol>

<ol type="A" start="3">
  <li>세 번째 범주</li>
  <li>네 번째 범주</li>
</ol>

단계나 순위는 ol을 사용합니다. type의 1, a, A, i, I로 번호 형식을 정하고 start, value, reversed로 시작 번호, 개별 번호와 역순을 설정할 수 있습니다.

설명 목록

<dl>
  <dt>HTML</dt>
  <dd>웹 콘텐츠의 구조와 의미를 표현하는 마크업 언어</dd>
  <dt>CSS</dt>
  <dd>웹 문서의 표현과 배치를 정의하는 스타일시트 언어</dd>
  <dt>JavaScript</dt>
  <dd>동작과 데이터 처리를 추가하는 프로그래밍 언어</dd>
</dl>

용어와 설명처럼 서로 짝을 이루는 목록은 dl, 용어는 dt, 설명은 dd를 사용합니다.

2.10 표

표는 행과 열의 관계를 가진 데이터를 표현하며 레이아웃에 사용하지 않습니다. table은 전체 표, caption은 제목, tr은 행, th는 머리글 셀, td는 데이터 셀입니다. thead, tbody, tfoot으로 행 그룹을 나눕니다.

<table>
  <caption>프로젝트 참여 현황</caption>
  <thead>
    <tr>
      <th scope="col">이름</th>
      <th scope="col">역할</th>
      <th scope="col">상태</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">홍길동</th>
      <td>프론트엔드</td>
      <td>진행 중</td>
    </tr>
  </tbody>
</table>

scope="col"은 열 머리글, scope="row"는 행 머리글을 나타냅니다. 과거의 border 속성 대신 CSS로 테두리를 표현합니다. rowspan은 여러 행, colspan은 여러 열에 걸친 셀을 만듭니다.

<table>
  <caption>주간 시간표</caption>
  <thead>
    <tr>
      <th rowspan="2" scope="col">교시</th>
      <th colspan="5" scope="colgroup">요일</th>
    </tr>
    <tr>
      <th scope="col">월</th><th scope="col">화</th>
      <th scope="col">수</th><th scope="col">목</th><th scope="col">금</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">1교시</th>
      <td>컴퓨터개론</td><td></td><td>웹프로그래밍</td><td></td><td></td>
    </tr>
    <tr>
      <th scope="row">2교시</th>
      <td></td><td>머신러닝</td><td></td><td>웹과인터넷</td><td></td>
    </tr>
  </tbody>
</table>

병합이 많은 표는 보조 기술에서 관계를 파악하기 어려우므로 가능한 단순하게 만듭니다. 자세한 내용은 MDN 표 접근성을 참고합니다.

2.11 이미지와 멀티미디어

이미지

<img
  src="https://images.unsplash.com/photo-1498050108023-c5249f4df085?w=600"
  alt="노트북 화면에 코드 편집기가 열린 개발 작업 공간"
  width="600"
  height="400"
/>

예제 이미지는 Christopher Gower가 Unsplash에 공개한 사진을 사용합니다.

  • src: 이미지 경로
  • alt: 이미지를 보지 못할 때 목적과 정보를 전달하는 대체 텍스트
  • width, height: 표시 크기와 배치 공간
  • loading="lazy": 화면에서 먼 이미지의 지연 로딩
  • title: 보충 정보이며 alt를 대신하지 않음

과거의 border, align과 인라인 style 같은 표현은 CSS로 분리합니다. 장식 이미지는 alt=""로 둡니다. 이미지와 설명이 한 단위면 figure와 figcaption을 사용합니다.

<figure>
  <img src="images/wireframe.png" alt="포트폴리오 첫 화면의 와이어프레임" />
  <figcaption>그림 1. 포트폴리오 초기 설계</figcaption>
</figure>

오디오

<audio controls preload="metadata">
  <source src="media/introduction.mp3" type="audio/mpeg" />
  <source src="media/introduction.ogg" type="audio/ogg" />
  브라우저가 오디오 재생을 지원하지 않습니다.
</audio>

src는 파일 경로, controls는 재생 UI, autoplay는 자동 재생 요청, loop는 반복, muted는 초기 음소거, preload는 미리 불러올 범위를 제안합니다. 여러 형식은 source로 제공합니다. 자동 재생은 브라우저 정책에 제한될 수 있고 사용자에게 불편을 줄 수 있습니다. 음성 정보에는 대본 같은 텍스트 대안을 제공합니다.

비디오

<video controls width="720" height="405" poster="images/video-cover.jpg">
  <source src="media/demo.mp4" type="video/mp4" />
  <track kind="captions" src="media/demo-ko.vtt" srclang="ko" label="한국어" default />
  브라우저가 비디오 재생을 지원하지 않습니다.
</video>

width와 height는 크기, poster는 재생 전 표지입니다. 오디오와 마찬가지로 controls, autoplay, loop, muted, preload를 사용할 수 있습니다. track은 자막을 제공합니다.

2.12 공간 분할과 범용 컨테이너

div는 여러 요소를 블록으로 묶고 span은 문장 안 일부를 묶는, 특별한 의미가 없는 범용 컨테이너입니다.

<div class="project-card">
  <h2>일정 관리 서비스</h2>
  <p>할 일을 기록하고 상태별로 분류합니다.</p>
</div>
<p>현재 상태: <span class="status">개발 중</span></p>

CSS와 JavaScript의 대상을 묶을 때 유용하지만 적절한 의미 요소가 있다면 header, nav, main, section, article, footer, button 등을 먼저 사용합니다.

2.13 iframe

iframe은 현재 문서 안에 별도의 웹 문서를 삽입합니다.

<iframe
  src="https://example.com/demo"
  title="프로젝트 실행 화면"
  width="800"
  height="450"
  loading="lazy"
></iframe>

src는 문서 URL, title은 접근 가능한 이름, width와 height는 크기, name은 링크의 target이 참조할 이름입니다. sandbox로 권한을 제한하고 allow로 카메라·마이크·전체화면 등의 기능 정책을 지정할 수 있습니다.

<a href="demo-a.html" target="preview">예제 A</a>
<a href="demo-b.html" target="preview">예제 B</a>
<iframe name="preview" title="선택한 예제 미리보기"></iframe>

과거의 scrolling 속성은 사용하지 않습니다. 외부 사이트는 보안 정책으로 삽입을 거부할 수 있으며, 신뢰할 수 없는 콘텐츠는 보안과 개인정보 위험을 만듭니다.

2.14 입력 양식

입력 양식(form)은 사용자가 웹사이트에 정보를 전달하는 인터페이스입니다. 로그인, 검색, 회원가입, 게시물 작성, 상품 주문처럼 목적은 다르지만 모두 값을 입력받고, 입력값을 확인하고, 서버나 JavaScript에 전달하는 과정을 가집니다.

폼을 설계할 때는 입력 요소를 화면에 배치하는 것만으로 충분하지 않습니다. 사용자가 무엇을 입력해야 하는지 알 수 있는 이름, 키보드로 이동할 수 있는 순서, 오류를 이해할 수 있는 안내, 서버가 값을 식별할 수 있는 name이 함께 필요합니다. HTML은 이러한 관계를 label, fieldset, 입력 유형과 검증 속성으로 표현합니다.

form과 GET·POST

<form action="/contact" method="post">
  <label for="name">이름</label>
  <input type="text" id="name" name="name" />
  <button type="submit">보내기</button>
</form>

form은 입력 데이터를 묶어 제출합니다. action은 처리 URL, method는 요청 방식, name은 폼 이름, enctype은 전송 데이터의 인코딩 방식입니다.

제출 버튼을 누르면 브라우저는 form 안에서 name을 가진 성공적인 폼 컨트롤의 값을 수집합니다. 예제에서 사용자가 이름에 홍길동을 입력하면 서버에는 name=홍길동과 같은 이름-값 쌍이 전달됩니다. 화면에서 요소를 찾는 id와 서버에 전달할 키인 name은 목적이 다르므로 둘 다 필요한 경우가 많습니다.

GET은 데이터를 URL 쿼리 문자열에 포함하므로 검색과 필터처럼 주소를 공유해도 되는 요청에 적합합니다. HTML 표준이 모든 환경에 동일한 “2,048자 제한”을 정한 것은 아니지만 브라우저와 서버별 실용적 제한이 있습니다. 민감한 데이터는 URL에 노출되므로 GET으로 보내지 않습니다.

POST는 데이터를 일반적으로 요청 본문에 포함하며 등록, 수정과 로그인 등에 사용합니다. POST 자체가 암호화나 보안을 보장하지 않습니다. HTTPS와 서버 측 인증, 권한 검사, 입력 검증이 필요합니다. MDN form method에서 현재 정의를 확인할 수 있습니다.

label과 input

<label for="user-name">이름</label>
<input type="text" id="user-name" name="userName" autocomplete="name" required />

label의 for와 입력 요소의 id를 같게 연결합니다. name은 제출 데이터의 키이며, name이 없으면 일반적인 폼 제출 데이터에 포함되지 않습니다. placeholder는 입력 예시이지 label을 대신하지 않습니다.

label이 필요한 이유

label은 입력란의 이름을 화면에 보여주는 텍스트 이상의 역할을 합니다. 브라우저와 보조 기술에 “이 설명은 이 입력 요소의 이름”이라는 관계를 전달합니다. 연결된 label을 클릭하면 입력 요소로 초점이 이동하므로, 작은 checkbox나 radio도 더 넓은 영역을 클릭해 선택할 수 있습니다.

  • 화면 낭독기는 입력 요소에 초점이 갔을 때 label을 읽어 입력 목적을 알려줍니다.
  • 음성 입력 사용자는 화면에 보이는 label 이름으로 컨트롤을 선택할 수 있습니다.
  • label이 없으면 placeholder가 사라진 뒤 입력값의 의미를 다시 확인하기 어렵습니다.
  • aria-label은 화면에 보이는 label을 만들 수 없는 예외적인 상황에 사용할 수 있지만, 일반적인 폼에서는 보이는 <label>을 우선합니다.

id, for, name의 차이

속성 역할 예제에서의 값
id 현재 문서에서 입력 요소를 고유하게 식별 user-name
for label이 설명하는 입력 요소의 id를 참조 user-name
name 폼 제출 시 서버에 전달되는 데이터의 키 userName
value 사용자가 입력하거나 선택하여 제출하는 값 예: 홍길동

for와 id가 다르면 label을 클릭해도 입력란으로 초점이 이동하지 않습니다. name이 없으면 화면에서는 정상적으로 입력되더라도 일반적인 폼 제출 데이터에서는 빠집니다. 여러 요소에 같은 id를 사용하면 label과 링크, JavaScript가 어느 요소를 참조해야 하는지 모호해집니다.

label 안에 입력 요소를 넣는 암시적 연결도 가능합니다.

<label>
  이메일
  <input type="email" name="email" autocomplete="email" required />
</label>

다만 for와 id를 사용하는 명시적 연결은 구조가 분리되어도 관계가 분명하고 다양한 보조 기술에서 일관되게 처리되므로 수업 예제의 기본 방식으로 사용합니다.

경고placeholder는 label이 아닙니다

placeholder="name@example.com"은 입력 형식의 예시를 보여줄 수 있지만, 사용자가 값을 입력하면 사라집니다. 색상 대비도 본문보다 낮을 수 있으므로 입력란의 이름이나 필수 조건을 placeholder에만 적지 않습니다.

select, optgroup과 multiple

<label for="role">관심 역할</label>
<select id="role" name="role">
  <option value="">선택하세요</option>
  <option value="frontend" selected>프론트엔드</option>
  <option value="backend">백엔드</option>
</select>

<label for="skills">사용 기술</label>
<select id="skills" name="skills" multiple size="5">
  <optgroup label="웹 기본">
    <option value="html">HTML</option>
    <option value="css">CSS</option>
    <option value="javascript">JavaScript</option>
  </optgroup>
  <optgroup label="라이브러리">
    <option value="react">React</option>
  </optgroup>
</select>

하나의 정해진 선택지는 select와 option, 복수 선택은 multiple, 선택지 그룹은 optgroup을 사용합니다.

option의 화면 텍스트는 사용자에게 보이는 설명이고 value는 서버로 제출되는 값입니다. 예를 들어 사용자가 “프론트엔드”를 선택하면 role=frontend가 제출됩니다. 첫 option의 value=""는 아직 의미 있는 값을 고르지 않은 상태를 나타내며 required와 함께 사용할 수 있습니다.

multiple이 있는 select는 운영체제에 따라 Ctrl, Command, Shift 같은 보조 키가 필요할 수 있어 초보 사용자에게 선택 방법이 명확하지 않을 수 있습니다. 선택지가 적고 여러 개를 고르는 것이 중요하다면 checkbox 그룹이 더 이해하기 쉬운지 함께 검토합니다. optgroup은 긴 선택지를 시각적·의미적 범주로 묶지만 그룹 자체를 선택하는 기능은 아닙니다.

textarea와 button

<label for="message">문의 내용</label>
<textarea id="message" name="message" rows="8" cols="40"></textarea>

<button type="submit">전송</button>
<button type="reset">초기화</button>
<button type="button">일반 버튼</button>

여러 줄 입력은 textarea입니다. 폼 안 button의 기본 타입은 submit이므로 제출용이 아닌 버튼에는 type="button"을 명시합니다. reset은 입력을 한 번에 지우므로 필요한 경우에만 사용합니다.

textarea의 초기값은 value 속성이 아니라 시작 태그와 종료 태그 사이에 작성합니다. rows와 cols는 대략적인 표시 크기를 제안하며 실제 너비와 높이는 CSS로 조정할 수 있습니다. 입력 가능한 길이는 minlength와 maxlength로 제한합니다.

<label for="introduction">자기소개</label>
<textarea
  id="introduction"
  name="introduction"
  rows="6"
  minlength="20"
  maxlength="500"
  aria-describedby="introduction-help"
></textarea>
<p id="introduction-help">20자 이상 500자 이하로 작성하세요.</p>

도움말과 오류 메시지는 입력 요소 가까이에 표시하고 aria-describedby로 연결할 수 있습니다. 버튼의 텍스트는 “확인”처럼 모호한 표현보다 “회원가입”, “문의 보내기”, “프로젝트 저장”처럼 실행 결과를 구체적으로 설명하는 편이 좋습니다.

fieldset과 legend

<fieldset>
  <legend>연락 방법</legend>
  <input type="radio" id="contact-email" name="contact" value="email" />
  <label for="contact-email">이메일</label>
  <input type="radio" id="contact-phone" name="contact" value="phone" />
  <label for="contact-phone">전화</label>
</fieldset>

관련 폼 컨트롤은 fieldset, 그룹 이름은 legend로 제공합니다. 과거 예제처럼 fieldset에 width와 height 속성을 쓰지 않고 CSS로 크기를 정합니다.

개별 label과 그룹 이름은 모두 필요합니다

radio와 checkbox는 각 선택지의 label만으로는 “무엇에 대한 선택인지” 알기 어려울 수 있습니다. 위 예제에서 “이메일”, “전화”는 개별 선택지이고 “연락 방법”은 두 선택지를 묶는 질문입니다. fieldset과 legend는 이 질문과 선택지의 관계를 브라우저와 보조 기술에 전달합니다.

<fieldset>
  <legend>수강 가능한 요일을 모두 선택하세요.</legend>

  <input type="checkbox" id="day-mon" name="days" value="monday" />
  <label for="day-mon">월요일</label>

  <input type="checkbox" id="day-wed" name="days" value="wednesday" />
  <label for="day-wed">수요일</label>

  <input type="checkbox" id="day-fri" name="days" value="friday" />
  <label for="day-fri">금요일</label>
</fieldset>
  • 같은 질문에 속한 radio는 같은 name을 가져야 하나만 선택됩니다.
  • checkbox는 같은 name을 사용할 수 있으며 선택된 값들이 각각 제출됩니다.
  • legend는 fieldset의 첫 번째 자식으로 작성하는 것이 일반적입니다.
  • fieldset disabled를 지정하면 그룹 안의 대부분의 폼 컨트롤을 한 번에 비활성화할 수 있습니다.
  • fieldset은 단순히 테두리를 그리는 요소가 아닙니다. 테두리가 필요 없으면 CSS로 숨기되 의미 구조는 유지합니다.
노트fieldset을 사용하면 좋은 경우

배송지 종류, 연락 방법, 약관 동의, 설문 문항처럼 하나의 질문 아래 여러 입력 요소가 모이는 경우에 사용합니다. 이름과 이메일처럼 각각 독립된 텍스트 입력을 무조건 하나의 fieldset으로 묶을 필요는 없습니다.

datalist와 output

<label for="browser">주로 사용하는 브라우저</label>
<input id="browser" name="browser" list="browser-options" />
<datalist id="browser-options">
  <option value="Chrome"></option>
  <option value="Edge"></option>
  <option value="Firefox"></option>
  <option value="Safari"></option>
</datalist>

datalist는 추천 값을 제공하지만 목록 밖의 값도 입력할 수 있습니다. output은 계산 결과를 나타냅니다.

datalist와 select의 차이

select는 제공된 option 가운데 하나 또는 여러 개를 선택하게 합니다. 반면 datalist는 text 계열 input에 자동완성 후보를 연결할 뿐이므로 사용자가 목록에 없는 값도 직접 입력할 수 있습니다.

요구 사항 적절한 요소
반드시 지정된 부서 중 하나를 선택 select
자주 사용하는 도시를 추천하지만 다른 도시도 허용 input + datalist
소수의 항목을 화면에 모두 보여주고 하나 선택 radio 그룹

input의 list="browser-options" 값과 datalist의 id="browser-options"가 일치해야 연결됩니다. datalist의 option은 추천값이며 데이터 검증 규칙이 아닙니다. 허용 가능한 값이 제한되어 있다면 서버에서 다시 검사해야 합니다. 또한 datalist의 표시 방식과 접근성 지원은 브라우저에 따라 차이가 있을 수 있으므로 핵심 작업에서는 직접 테스트합니다.

<form oninput="result.value = Number(x.value) * Number(y.value)">
  <label for="x">가로</label><input type="number" id="x" name="x" value="10" />
  <label for="y">세로</label><input type="number" id="y" name="y" value="20" />
  <output name="result" for="x y">200</output>
</form>

인라인 이벤트는 원리 설명에는 쓸 수 있으나 실제 프로젝트에서는 JavaScript 파일에서 이벤트를 등록하는 방식을 권장합니다.

output의 역할

output은 계산기 결과, 견적 금액, 선택한 범위의 현재 값처럼 사용자의 입력으로 계산된 결과를 나타냅니다. 단순한 장식용 숫자가 아니라 “계산 결과”라는 의미를 가지며 폼과 연결할 수 있습니다.

  • name: 폼에서 결과를 식별하는 이름입니다.
  • for="x y": 결과 계산에 사용된 입력 요소의 id를 공백으로 나열합니다.
  • 요소 안의 텍스트 200: JavaScript가 실행되지 않았거나 아직 계산하지 않았을 때 보이는 초기 내용입니다.

output은 값을 계산하지 않습니다. JavaScript가 계산한 값을 output.value나 텍스트로 반영해야 합니다. 결과가 자주 바뀌고 즉시 알려야 하는 인터페이스라면 화면 낭독기 알림이 필요한지 검토하되, 지나친 실시간 알림은 오히려 사용을 방해할 수 있습니다.

2.15 input 공통 속성

속성 의미
readonly 값은 제출되지만 사용자가 수정할 수 없음
disabled 조작할 수 없고 일반적인 제출에서도 제외됨
autocomplete 브라우저 자동완성 목적 지정
autofocus 처음 초점을 요청하며 남용에 주의
placeholder 입력 예시이며 label을 대신하지 않음
required 필수 입력 또는 선택
spellcheck 맞춤법 검사 사용 여부 제안
min, max, step 숫자와 날짜의 범위 및 간격
minlength, maxlength 문자열 길이 제한
pattern 입력값이 만족해야 할 정규 표현식
value, checked 초기값과 초기 선택 상태

브라우저 검증은 사용자 피드백일 뿐 보안 수단이 아닙니다. 서버에서도 모든 입력을 다시 검증합니다.

속성은 입력 목적과 데이터 유형에 맞게 조합합니다. 예를 들어 이메일 입력에 type="email", autocomplete="email", required를 함께 사용하면 모바일 키보드와 자동완성, 기본 형식 검사, 필수 입력 안내를 동시에 지원할 수 있습니다.

readonly와 disabled는 비슷해 보이지만 제출 동작이 다릅니다. readonly 값은 일반적으로 제출되고 키보드 초점도 받을 수 있지만 사용자가 수정할 수 없습니다. disabled 요소는 조작할 수 없고 일반적인 폼 제출 데이터에서도 제외됩니다. 서버가 반드시 받아야 하는 값을 disabled 입력에만 두면 데이터가 전달되지 않을 수 있습니다.

브라우저의 required, pattern, min, max 검증은 사용자가 실수를 빨리 발견하도록 돕습니다. 개발자 도구나 직접 만든 HTTP 요청으로 우회할 수 있으므로 데이터의 신뢰성·권한·보안을 보장하지는 않습니다. 서버는 클라이언트에서 전달된 모든 값을 신뢰하지 않고 다시 검사해야 합니다.

2.16 input 유형

text, password와 button

<label for="account-id">아이디</label>
<input type="text" id="account-id" name="accountId" minlength="4" required />

<label for="password">비밀번호</label>
<input type="password" id="password" name="password" minlength="8" required />

<input type="button" value="미리보기" />

text는 한 줄 텍스트, password는 입력 문자를 화면에서 가립니다. 화면에서 가리는 것이 암호화는 아닙니다. 일반 버튼은 input보다 내용을 자유롭게 넣을 수 있는 <button type="button">이 더 유연합니다.

radio와 checkbox

<fieldset>
  <legend>수강 형태</legend>
  <input type="radio" id="offline" name="courseType" value="offline" checked />
  <label for="offline">대면</label>
  <input type="radio" id="online" name="courseType" value="online" />
  <label for="online">온라인</label>
</fieldset>

<fieldset>
  <legend>관심 기술</legend>
  <input type="checkbox" id="html" name="skills" value="html" />
  <label for="html">HTML</label>
  <input type="checkbox" id="css" name="skills" value="css" />
  <label for="css">CSS</label>
</fieldset>

같은 name의 radio는 하나만 선택하며 checkbox는 여러 독립 항목을 선택합니다.

날짜와 시간

<input type="date" name="date" min="2026-01-01" max="2026-12-31" />
<input type="month" name="month" />
<input type="week" name="week" />
<input type="time" name="time" />
<input type="datetime-local" name="meeting" />

브라우저와 운영체제마다 선택 UI가 다를 수 있습니다. datetime-local은 시간대 없이 사용자의 지역 날짜와 시간을 입력받습니다.

color, number와 range

<input type="color" name="themeColor" value="#3366ff" />
<input type="number" name="experience" min="0" max="120" step="1" />
<input type="range" name="progress" min="0" max="100" value="20" />

range는 현재 값을 정확히 읽기 어려울 수 있으므로 텍스트나 output으로 함께 표시합니다.

email, url과 tel

<input type="email" name="email" autocomplete="email" required />
<input type="url" name="website" placeholder="https://example.com" />
<input
  type="tel"
  name="phone"
  autocomplete="tel"
  placeholder="010-1234-5678"
  pattern="010-[0-9]{4}-[0-9]{4}"
/>

email과 url은 브라우저가 기본 형식을 검사합니다. tel은 자동으로 형식을 제한하지 않으므로 필요하면 pattern과 안내 문구를 제공합니다.

file, submit과 reset

<input type="file" name="portfolioFile" accept=".pdf,image/png,image/jpeg" />
<button type="submit">전송</button>
<button type="reset">초기화</button>

파일 전송 form에는 보통 method="post"와 enctype="multipart/form-data"가 필요합니다. accept는 선택 안내일 뿐이므로 서버에서 파일 형식, 크기와 내용을 검사합니다.

2.18 class와 id

class는 여러 요소를 같은 그룹으로 묶습니다. 하나의 요소는 여러 class를 가질 수 있고 같은 class는 반복할 수 있습니다.

<p class="content featured">첫 번째 콘텐츠</p>
<p class="content">두 번째 콘텐츠</p>

CSS에서는 .content로 선택합니다. id는 문서 안의 요소 하나를 고유하게 식별합니다.

<p id="introduction">첫 번째 문단</p>

CSS에서는 #introduction, 페이지 링크에서는 href="#introduction", label에서는 for="introduction"처럼 참조합니다. 중복 id는 링크, 라벨과 JavaScript 선택을 오작동하게 합니다.

2.19 시맨틱 요소

시맨틱 HTML은 요소 이름이 콘텐츠의 역할을 설명하도록 작성하는 방식입니다.

요소 의미
header 페이지 또는 구획의 머리말
nav 주요 탐색 링크 묶음
main 문서의 핵심 콘텐츠. 일반적으로 문서당 하나
section 하나의 주제로 묶인 구획. 보통 제목을 가짐
article 독립적으로 배포·재사용 가능한 글, 카드, 게시물
aside 본문과 간접적으로 관련된 보충 콘텐츠
footer 작성자, 저작권, 관련 링크 등 마무리 정보
figure, figcaption 독립 콘텐츠와 그 설명
time 기계가 읽을 수 있는 날짜와 시간
address 문서나 article 작성자의 연락처

          <li><a href="#about">소개</a></li>

        </ul>
      </nav>
    </header>

    <main>
      <section id="about">
        <h1>웹 개발자 홍길동</h1>
        <p>웹 표준과 접근성을 고려한 서비스를 만듭니다.</p>

      <section id="projects">
        <h2>프로젝트</h2>
        <article>
          <header>
            <h3>학습 기록 서비스</h3>

          </header>
          <p>학습 내용과 진행 상태를 기록하는 웹 애플리케이션입니다.</p>

      <aside>
        <h2>관련 링크</h2>

의미 있는 요소가 접근성 문제를 모두 해결하지는 않습니다. 제목 계층, 키보드 조작, 대체 텍스트, 폼 라벨과 색상 대비를 함께 고려해야 하지만 시맨틱 HTML은 접근 가능한 웹의 중요한 출발점입니다.

2.21 HTML 검사와 디버깅

브라우저는 잘못된 HTML을 가능한 범위에서 복구하므로 화면이 보인다고 문서가 올바른 것은 아닙니다. 개발자 도구의 Elements 패널에서 실제 DOM을 확인하고 W3C Nu HTML Checker로 문법을 검사합니다.

  • html에 문서 언어가 있는가?
  • charset, viewport와 의미 있는 title이 있는가?
  • 요소가 올바르게 중첩되었는가?
  • id가 중복되지 않는가?
  • 제목 단계가 논리적인가?
  • 정보성 이미지에 적절한 alt가 있는가?
  • 폼 컨트롤에 label이 연결되었는가?
  • 링크 텍스트만 읽어도 목적지를 알 수 있는가?
  • 표에 caption과 머리글이 있는가?

문제 1. 자기소개 영역 만들기

다음 조건을 만족하는 자기소개 영역을 직접 작성하세요.

  • section의 id는 about으로 지정합니다.
  • h2 제목, 프로필 이미지, 두 개의 자기소개 문단을 넣습니다.
  • 이미지에는 내용을 설명하는 alt를 작성합니다.
  • 중요한 목표 하나를 strong으로 표시합니다.
  • 취미 세 가지를 ul로 작성합니다.
<section id="about">
  <!-- 제목, 이미지, 소개 문단과 취미 목록을 작성하세요. -->

문제 2. 이동 가능한 개인 페이지 구조 만들기

다음 조건을 만족하는 페이지 구조를 직접 작성하세요.

  • header, nav, main, footer를 모두 사용합니다.
  • nav에 소개, 기술, 프로젝트 링크를 만듭니다.
  • main 안에 id가 about, skills, projects인 section을 만듭니다.
  • 각 링크를 누르면 연결된 section으로 이동해야 합니다.
  • 프로젝트 section 안에는 하나 이상의 article을 작성합니다.
<body>
  <header>
    <!-- 페이지 제목과 nav를 작성하세요. -->
  </header>
  <main>
    <!-- about, skills, projects section을 작성하세요. -->
  </main>
  <footer>
    <!-- 이메일 링크를 작성하세요. -->
  </footer>
</body>
