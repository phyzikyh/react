# 3주차 강의 슬라이드 작성 지침

> 대상 교재: `week03_lecture.qmd` (JSX와 엘리먼트 렌더링)
> 목적: 이론 원고를 "읽는 문서"에서 "말하며 보여 주는 슬라이드"로 옮기기 위한 설계 지침

---

## 0. 이 강의의 한 줄 핵심

> **개발자가 쓴 JSX(설명) → React가 계산 → 브라우저 DOM(실제 화면)**

모든 슬라이드는 이 파이프라인의 어느 단계를 다루는지 스스로 위치를 가져야 합니다.
학생이 수업 끝에 이 한 문장만 확실히 기억하면 3주차는 성공입니다.

---

## 1. 슬라이드 설계 5원칙

1. **한 슬라이드 = 한 메시지.** 교재의 한 소절(`##`)이 곧 한 슬라이드가 아닙니다. 소절 안의 핵심 주장 하나만 슬라이드 제목(또는 상단 한 줄)으로 뽑습니다.
2. **문장을 붙여 넣지 않는다.** 교재 문장은 "말로 설명할 대본"이고, 슬라이드에는 **키워드·그림·코드**만 올립니다. 슬라이드 글머리표는 슬라이드당 3~5개, 한 줄 이내.
3. **코드는 통째로 보여 주지 말고 쪼갠다.** 긴 코드는 한 번에 다 띄우지 말고, 줄 강조(highlight)로 "지금 보는 줄"만 밝혀 순서대로 읽습니다. 교재가 이미 코드를 조각조각 나눠 설명하므로 그 순서를 그대로 활용합니다.
4. **개념 슬라이드와 실습(데모) 슬라이드를 색/아이콘으로 구분한다.** 학생이 "지금은 이해할 시간 / 지금은 따라 할 시간"을 바로 알게 합니다.
5. **그림이 있으면 그림이 주인공.** `그림 3.1`(DOM), `그림 3.2`(세 파일 흐름)는 슬라이드 한 장을 통째로 차지하게 하고, 말로 짚어 가며 설명합니다.

### 2장. JSX란 무엇인가 (5장 · 20분)

| # | 슬라이드 | 담을 것 | 말할 것 / 방식 |
|---|---|---|---|
| 9 | JSX 정의 | `const title = <h1>…</h1>;` 한 줄 | "이건 문자열이 아니다"를 강조 |
| 10 | **JSX ≠ HTML** ⭐⭐⭐ | 같은 `<main>`을 .html에 / .jsx 함수 안에 나란히 | "태그 모양이 아니라 **놓인 위치**가 종류를 정한다" |
| 11 | JSX ↔ createElement | JSX 1줄 vs createElement 1줄 나란히 | "JSX는 이 호출의 읽기 쉬운 표기"(개념만, 실습 아님) |
| 12 | JSX로 뭘 만드나 | 영역표(머리말/소개/콘텐츠/입력/바닥글) 축약 | "구조·내용은 JSX, 색·배치는 CSS, 동작은 JS" |
| 13 | 영역 만들기 🖥️데모 | 머리말·소개 중 1~2개만 | App.jsx에 **붙여넣어 실행**, 나머지는 "형태만 다르다" |

## 3. 파트별 "어떻게 설명하나" (⭐⭐⭐ 개념 심화)

### DOM (슬라이드 3)
- **비유 먼저, 정의 나중.** "HTML 파일은 종이에 적은 설계도일 뿐, 브라우저가 그걸 읽어 조작 가능한 실제 건물을 메모리에 짓는다—그 건물이 DOM."
- `그림 3.1`을 왼→오로 손가락으로 짚으며: "이 텍스트가 → 브라우저를 거쳐 → 이 트리가 된다."
- 마무리 한 문장: **"화면을 바꾼다 = HTML 파일이 아니라 이 DOM 트리를 바꾼다."** → React가 할 일의 예고.

### 세 파일의 흐름 (슬라이드 7)
- 무대 비유 고정: **index.html = 빈 무대(`#root`), main.jsx = 무대와 공연 연결, App.jsx = 공연 내용.**
- `그림 3.2`의 화살표를 순서대로 따라가며 "누가 누구를 부르는지"만 말합니다. 코드는 아직 안 봐도 됩니다.
- 여기서 학생이 가장 헷갈리는 것: "그래서 **내가 고칠 파일은 뭐냐?**" → "거의 항상 App.jsx"로 못박기.

### JSX ≠ HTML (슬라이드 10)
- 똑같이 생긴 `<main>` 두 개를 나란히 놓고 질문 던지기: "이 둘은 같은가 다른가?"
- 답: **"태그 모양은 같아도, .html에 있으면 HTML / .jsx 함수의 반환값이면 JSX. 위치와 쓰임이 종류를 정한다."**
- 오해 교정 포인트: "JSX는 HTML을 복사하는 게 아니라, **지금 데이터로 어떤 화면이어야 하는지를 JS 값으로 적는 것.**"

### 엘리먼트 ≠ DOM (슬라이드 18)
- 슬라이드 3(DOM)과 **의도적으로 다시 연결**: "아까 그 DOM 기억나죠? React 엘리먼트는 아직 DOM이 **아니고**, '이런 DOM을 만들어 달라'고 적은 메모다."
- 이게 5주차 state·리렌더링의 토대이므로, 지금은 **개념만 확실히** 심고 깊이 들어가지 않습니다.

## 4. 슬라이드 유형별 템플릿

**① 개념 슬라이드**
```
[제목: 한 줄 주장]
· 키워드 3~4개 (한 줄씩)
· 그림 또는 한 줄 비유
(문단 금지)
```

**② 코드 슬라이드**
```
[제목: 이 코드가 하는 일]
```코드 (6~10줄 이내, 지금 설명할 줄만 강조)```
→ 화살표 한 줄로 결과/의미
```
- 긴 코드는 여러 장으로 쪼개고, 강조 줄만 옮겨 가며 진행.

**③ 데모(실습) 슬라이드** 🖥️
```
[🖥️ 함께 해봅시다]
· 붙여넣을 코드 위치: src/App.jsx
· 기대 결과: (한 줄)
(에디터/브라우저로 전환)
```
- 슬라이드는 "무엇을·어디에" 안내만. 실제 코드는 에디터에서.

**④ 비교 슬라이드**
```
[제목: A vs B]
| 구분 | A | B |   ← 2~4행만
```
- 슬라이드 10, 18, 20에 사용.

**⑤ 정리 슬라이드**
```
[핵심 3가지]
1. …  2. …  3. …
```

## 5. 자주 하는 실수 (슬라이드 만들 때)

- ❌ 교재 문단을 그대로 복사 → ✅ 키워드/그림으로 축약, 문장은 입으로
- ❌ main.jsx 전체 코드를 한 장에 다 띄우고 줄줄이 설명 → ✅ 에디터로 실제 파일 보며 설명, 슬라이드엔 최종형 1장
- ❌ 3장(작성 규칙)을 규칙마다 한 장씩 정성껏 → ✅ "함정 모음"으로 압축, 시간은 개념(1·2·4장)에
- ❌ 데모 코드가 붙여넣어 실행되는지 미확인 → ✅ 수업 전 App.jsx에 실제로 붙여 실행 테스트(3주차 예제는 붙여넣기 실행형)
- ❌ 그림을 작게 넣고 옆에 글 채우기 → ✅ 그림은 한 장 전체, 말로 짚기

## 7. (선택) Quarto reveal.js로 만들 때

교재와 같은 톤·색을 유지하려면 Quarto reveal.js 포맷을 그대로 쓸 수 있습니다.

- 새 파일 `week03_slides.qmd`, 헤더에 `format: revealjs`.
- `##` = 슬라이드 한 장. 코드 줄 강조는 ```` ```{.jsx code-line-numbers="2-4"} ````.
- `그림 3.1/3.2`의 mermaid 블록은 그대로 복사해 재사용(색 classDef 유지).
- 데모 슬라이드에는 `{background-color="#f1fbf8"}`처럼 배경색으로 개념/실습 구분.
- 발표자 노트는 `::: {.notes}` 블록에 위 "말할 것" 대본을 넣기.

필요하면 이 지침대로 `week03_slides.qmd` 뼈대(23장)를 바로 생성해 드릴 수 있습니다.
