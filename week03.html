4  3주차: JSX와 엘리먼트 렌더링

JavaScript 안에서 UI를 표현하고 브라우저 DOM에 반영하기

공개

2026년 9월 7일

5 JSX 개요

JSX는 JavaScript 파일 안에서 HTML과 비슷한 마크업을 작성할 수 있게 하는 JavaScript 문법 확장(syntax extension)입니다. JSX는 HTML도 아니고 별도의 템플릿 언어도 아닙니다. 작성된 JSX는 개발 도구에 의해 JavaScript 코드로 변환되고, React는 그 결과를 이용해 화면에 표시할 UI 구조를 계산합니다.

const element = <h1>안녕하세요, React!</h1>;

위 코드는 브라우저가 그대로 이해하는 일반 JavaScript 문법이 아닙니다. Vite 같은 개발 도구가 JSX를 변환한 뒤 브라우저에 전달합니다. React 공식 문서는 JSX를 “JavaScript 파일 안에 HTML과 유사한 마크업을 작성하게 하는 문법 확장”으로 설명합니다. JSX는 React 사용의 필수 조건은 아니지만 대부분의 React 프로젝트에서 UI를 간결하게 표현하기 위해 사용합니다. React 공식 문서: Writing Markup with JSX

노트JSX를 바라보는 관점

JSX를 HTML 문서를 그대로 복사하는 문법으로 이해하기보다, “현재 데이터에 따라 어떤 UI가 보여야 하는가를 JavaScript 값으로 표현하는 방법”으로 이해합니다.

6 JSX를 사용하는 이유

전통적인 웹 페이지에서는 HTML이 콘텐츠를, JavaScript가 동작을 담당하며 파일도 분리되는 경우가 많았습니다. 그러나 사용자 인터페이스가 복잡해지면 표시되는 마크업과 이를 결정하는 데이터 및 로직이 긴밀하게 연결됩니다. 예를 들어 로그인 여부에 따라 다른 메뉴를 보여주거나 프로젝트 상태에 따라 카드의 문구를 변경하려면 마크업과 렌더링 로직을 함께 살펴봐야 합니다.

JSX는 관련 있는 마크업과 렌더링 로직을 컴포넌트 안에 함께 둡니다.

function WelcomeMessage() {
  const userName = "홍길동";

  return (
    <section>
      <h1>{userName}님, 환영합니다.</h1>
      <p>오늘도 프로젝트를 한 단계 진행해 보세요.</p>
    </section>
  );
}

이 코드에서 userName이라는 데이터와 그 값을 표시하는 제목이 같은 컴포넌트에 있습니다. CSS는 여전히 별도 파일로 분리할 수 있습니다. JSX를 사용한다고 HTML, CSS와 JavaScript의 역할이 사라지는 것은 아닙니다. 관련 있는 UI 구조와 렌더링 계산을 한 단위로 관리하는 방식이 달라지는 것입니다.

7 React 엘리먼트와 DOM 요소

“엘리먼트”라는 용어는 문맥에 따라 구분해야 합니다.

  • HTML 요소: HTML 문서에 작성한 <h1>, <section> 등의 마크업 요소
  • React 엘리먼트: React가 UI 구조를 표현하는 값
  • DOM 노드: 브라우저가 실제 문서 트리에 만든 객체

JSX 표현식은 React가 처리할 수 있는 React 엘리먼트 또는 React 노드 값으로 변환됩니다. React는 이 값을 바탕으로 어떤 DOM 노드가 필요한지 계산하고 브라우저 DOM에 반영합니다.

const title = <h1 className="page-title">프로젝트 목록</h1>;

title에는 화면에 보이는 실제 h1 DOM 노드가 즉시 저장되는 것이 아닙니다. 어떤 h1을 렌더링할지 설명하는 React 값이 저장됩니다. React가 이 값을 root에 렌더링하고 commit 단계를 수행한 뒤 실제 DOM이 만들어집니다.

8 JSX 기본 규칙

JSX는 HTML과 유사하지만 JavaScript로 변환되기 때문에 몇 가지 엄격한 규칙을 따릅니다.

8.1 하나의 루트 요소 반환

컴포넌트는 여러 형제 요소를 그대로 반환할 수 없습니다.

// 잘못된 예
function Profile() {
  return (
    <h1>홍길동</h1>
    <p>프론트엔드 개발을 공부합니다.</p>
  );
}

하나의 부모 요소로 감싸야 합니다.

function Profile() {
  return (
    <section>
      <h1>홍길동</h1>
      <p>프론트엔드 개발을 공부합니다.</p>
    </section>
  );
}

불필요한 DOM 요소를 추가하고 싶지 않다면 Fragment를 사용합니다.

function Profile() {
  return (
    <>
      <h1>홍길동</h1>
      <p>프론트엔드 개발을 공부합니다.</p>
    </>
  );
}

짧은 <>...</> 문법은 Fragment를 나타냅니다. Fragment는 여러 요소를 하나로 그룹화하지만 실제 DOM에는 별도의 wrapper 요소를 만들지 않습니다. React 공식 문서: Fragment

8.2 모든 태그 닫기

HTML에서는 일부 종료 태그를 생략할 수 있지만 JSX에서는 모든 태그를 명확하게 닫아야 합니다.

// HTML에서 흔히 볼 수 있는 형태지만 JSX에서는 잘못됨
<img src="/images/profile.jpg" alt="프로필">
<br>
// 올바른 JSX
<img src="/images/profile.jpg" alt="프로필" />
<br />

내용이 있는 요소도 시작과 종료 태그를 모두 작성합니다.

<p>프로젝트를 소개합니다.</p>

8.3 올바르게 중첩하기

HTML과 마찬가지로 태그가 교차하면 안 됩니다.

// 잘못된 예
<p><strong>중요한 내용</p></strong>
// 올바른 예
<p><strong>중요한 내용</strong></p>

8.4 여러 줄 JSX를 괄호로 감싸기

한 줄 JSX는 바로 반환할 수 있습니다.

function Title() {
  return <h1>프로젝트</h1>;
}

여러 줄이라면 소괄호로 감싸 구조를 명확하게 합니다.

function Title() {
  return (
    <header>
      <h1>프로젝트</h1>
      <p>학기 동안 구현한 결과물입니다.</p>
    </header>
  );
}

return 다음 줄에 괄호 없이 JSX를 작성하면 JavaScript의 자동 세미콜론 삽입 때문에 undefined가 반환될 수 있습니다.

// 잘못된 예
function Title() {
  return
    <h1>프로젝트</h1>;
}

9 JSX 속성 작성법

JSX의 속성은 JavaScript 객체의 속성 이름으로 변환됩니다. 따라서 HTML 속성과 이름이 다른 경우가 있습니다.

9.1 className

HTML의 class는 JSX에서 className으로 작성합니다.

<!-- HTML -->
<section class="project-card"></section>
// JSX
<section className="project-card"></section>

class는 JavaScript에서 사용되는 예약어이며 React DOM 속성 이름과의 일관성을 위해 className을 사용합니다.

9.2 htmlFor

HTML label의 for는 JSX에서 htmlFor로 작성합니다.

<label htmlFor="email">이메일</label>
<input id="email" name="email" type="email" />

9.3 camelCase 속성

JSX에서는 많은 HTML과 SVG 속성을 camelCase로 작성합니다.

<button onClick={handleClick}>확인</button>
<input tabIndex={0} readOnly />
<svg strokeWidth={2}></svg>

HTML의 onclick, tabindex, readonly, SVG의 stroke-width는 JSX에서 각각 onClick, tabIndex, readOnly, strokeWidth가 됩니다. 다만 aria-*와 data-* 속성은 하이픈을 포함한 소문자 형태를 그대로 사용합니다.

<button
  aria-label="메뉴 열기"
  aria-expanded={false}
  data-testid="menu-button"
>
  메뉴
</button>

9.4 불리언 속성

값 없이 속성 이름만 작성하면 true로 처리됩니다.

<input required />
<button disabled>저장할 수 없음</button>

명시적으로 값을 제공할 수도 있습니다.

const isSaving = false;

<button disabled={isSaving}>저장</button>

10 중괄호로 JavaScript 사용하기

JSX 안의 중괄호 {}는 JavaScript 표현식을 삽입하는 창과 같습니다. React 공식 문서에서는 중괄호를 사용해 변수, 함수 호출과 객체 값을 마크업에 연결하는 방법을 설명합니다. React 공식 문서: JavaScript in JSX with Curly Braces

10.1 텍스트 안에서 변수 사용

function Greeting() {
  const name = "홍길동";
  return <h1>{name}님, 안녕하세요.</h1>;
}

문자열뿐 아니라 숫자와 계산 결과도 표시할 수 있습니다.

function Progress() {
  const completed = 3;
  const total = 15;

  return (
    <p>
      전체 {total}주 중 {completed}주를 완료했습니다.
      진행률은 {Math.round((completed / total) * 100)}%입니다.
    </p>
  );
}

중괄호에는 표현식(expression)을 작성합니다. 표현식은 하나의 값으로 평가되는 코드입니다. 변수 참조, 산술 연산, 문자열 결합, 함수 호출, 삼항 연산자 등이 포함됩니다.

<p>{2 + 3}</p>
<p>{userName.toUpperCase()}</p>
<p>{isComplete ? "완료" : "진행 중"}</p>

if, for, 변수 선언과 같은 문(statement)은 JSX 중괄호 안에 직접 작성할 수 없습니다. 필요한 계산은 return 전에 수행합니다.

function Status() {
  const score = 85;
  let message;

  if (score >= 80) {
    message = "목표를 달성했습니다.";
  } else {
    message = "조금 더 연습해 보세요.";
  }

  return <p>{message}</p>;
}

10.2 속성값에 표현식 사용

고정 문자열은 따옴표, JavaScript 값은 중괄호를 사용합니다.

function Avatar() {
  const imageUrl = "/images/profile.jpg";
  const description = "홍길동의 프로필 사진";

  return (
    <img
      className="avatar"
      src={imageUrl}
      alt={description}
      width={240}
      height={240}
    />
  );
}

다음 두 코드는 결과가 다릅니다.

<img src={imageUrl} alt={description} />
<img src="{imageUrl}" alt="{description}" />

첫 번째는 변수값을 사용하고, 두 번째는 {imageUrl}이라는 글자 자체를 문자열로 사용합니다.

10.3 함수 호출 결과 표시

function formatDate(date) {
  return new Intl.DateTimeFormat("ko-KR", {
    year: "numeric",
    month: "long",
    day: "numeric",
  }).format(date);
}

function Today() {
  const today = new Date(2026, 8, 7);
  return <time dateTime="2026-09-07">{formatDate(today)}</time>;
}

함수 호출도 하나의 값으로 평가되므로 중괄호 안에서 사용할 수 있습니다. 다만 렌더링 중 실행되는 함수는 외부 값을 변경하지 않는 순수한 계산이어야 합니다.

11 JSX에서 표시되는 값과 표시되지 않는 값

문자열과 숫자는 화면에 텍스트로 표시됩니다.

<p>{"React"}</p>
<p>{2026}</p>

null, undefined, true, false는 일반적으로 화면에 아무것도 표시하지 않습니다.

<p>{null}</p>
<p>{undefined}</p>
<p>{true}</p>
<p>{false}</p>

불리언 값을 글자로 보여주려면 변환해야 합니다.

const isComplete = false;

<p>완료 여부: {String(isComplete)}</p>
<p>상태: {isComplete ? "완료" : "진행 중"}</p>

일반 JavaScript 객체를 그대로 자식으로 렌더링하면 오류가 발생합니다.

const project = {
  title: "포트폴리오",
  status: "진행 중",
};

// 오류: 객체 자체는 React 자식으로 렌더링할 수 없음
<p>{project}</p>

필요한 속성을 선택해야 합니다.

<p>{project.title}</p>
<p>{project.status}</p>

객체 내용을 디버깅 목적으로 확인할 때는 문자열로 변환할 수 있습니다.

<pre>{JSON.stringify(project, null, 2)}</pre>

12 JSX의 style 속성

HTML의 style 속성은 문자열이지만 JSX의 style은 JavaScript 객체를 받습니다.

<!-- HTML -->
<p style="color: navy; background-color: lightyellow;">안내</p>
// JSX
<p style={{ color: "navy", backgroundColor: "lightyellow" }}>
  안내
</p>

겹친 중괄호가 새로운 JSX 문법을 의미하는 것은 아닙니다.

  • 바깥 {}: JSX 안에서 JavaScript 표현식을 사용
  • 안쪽 {}: JavaScript 객체 리터럴

객체를 변수로 분리하면 읽기 쉬워집니다.

function Notice() {
  const noticeStyle = {
    color: "#0550ae",
    backgroundColor: "#ddf4ff",
    padding: "1rem",
    borderRadius: "0.5rem",
  };

  return <p style={noticeStyle}>수업 자료가 업데이트되었습니다.</p>;
}

CSS 속성 이름은 background-color 대신 backgroundColor처럼 camelCase로 작성합니다. 숫자값은 일부 속성에서 px 단위로 해석되지만 단위가 필요한 값은 문자열로 제공합니다.

<div style={{ width: 320, lineHeight: 1.7, marginTop: "2rem" }} />

대부분의 일반 스타일은 className과 외부 CSS 파일로 관리하는 편이 재사용과 반응형 디자인에 유리합니다. style 객체는 데이터에 따라 동적으로 계산되는 제한적인 스타일에 활용합니다.

13 JSX 주석

JSX 마크업 안에서는 JavaScript 중괄호 안에 블록 주석을 작성합니다.

function Profile() {
  return (
    <section>
      {/* 대표 프로필 정보 */}
      <h1>홍길동</h1>
      <p>React를 공부하고 있습니다.</p>
    </section>
  );
}

JSX 밖의 JavaScript 영역에서는 일반 JavaScript 주석을 사용합니다.

// 프로젝트 상태를 나타내는 상수
const status = "진행 중";

/* 여러 줄에 걸친
   JavaScript 주석 */

14 특수문자와 문자열

JSX 텍스트 안에서 <와 >는 태그로 해석될 수 있습니다. 문자 자체를 표시하려면 HTML entity 또는 JavaScript 문자열 표현식을 사용합니다.

<p>3 &lt; 5이고, 10 &gt; 7입니다.</p>
<p>{"<section>은 문서 구획을 나타냅니다."}</p>

따옴표가 포함된 텍스트는 JSX 본문에 직접 작성할 수 있습니다.

<p>React에서 "렌더링"은 UI를 계산하는 과정입니다.</p>

속성 안에서는 따옴표 종류를 구분하거나 JavaScript 문자열을 사용합니다.

<img alt="홍길동의 '프로젝트 화면'" />
<img alt={'홍길동의 "프로젝트 화면"'} />

15 JSX가 JavaScript로 변환되는 방식

JSX는 최종적으로 JavaScript 호출로 변환됩니다. 다음 JSX를 생각해 살펴봅시다.

const element = (
  <h1 className="title">
    안녕하세요
  </h1>
);

개념적으로는 다음과 같은 React 엘리먼트 생성 코드에 대응합니다.

import { createElement } from "react";

const element = createElement(
  "h1",
  { className: "title" },
  "안녕하세요"
);

현대 JSX 변환은 react/jsx-runtime의 함수를 자동으로 사용할 수 있어 파일마다 React 자체를 import하지 않아도 되는 경우가 많습니다. 하지만 핵심 원리는 같습니다. JSX는 브라우저 DOM 문자열이 아니라 React가 UI를 계산할 수 있는 JavaScript 값으로 변환됩니다.

직접 createElement를 호출할 수도 있지만 JSX가 중첩 구조를 훨씬 읽기 쉽게 보여줍니다.

const element = createElement(
  "section",
  { className: "profile" },
  createElement("h1", null, "홍길동"),
  createElement("p", null, "프론트엔드 개발을 공부합니다.")
);
const element = (
  <section className="profile">
    <h1>홍길동</h1>
    <p>프론트엔드 개발을 공부합니다.</p>
  </section>
);

16 컴포넌트와 JSX의 관계

React 함수 컴포넌트는 JSX를 반환하는 JavaScript 함수입니다.

function Profile() {
  return (
    <article className="profile">
      <h2>홍길동</h2>
      <p>웹 표준과 React를 공부하고 있습니다.</p>
    </article>
  );
}

컴포넌트 이름은 대문자로 시작합니다. 소문자로 시작하는 JSX 태그는 브라우저 내장 요소로 처리되고, 대문자로 시작하는 태그는 사용자가 정의하거나 import한 컴포넌트로 처리됩니다.

function App() {
  return (
    <main>
      <h1>개발자 소개</h1>
      <Profile />
    </main>
  );
}

<main>과 <h1>은 DOM 요소가 되고 <Profile />은 React가 호출해야 할 컴포넌트를 나타냅니다. React는 Profile()을 렌더링하여 반환된 JSX 구조를 계속 계산합니다.

다음은 잘못된 컴포넌트 이름입니다.

function profile() {
  return <p>프로필</p>;
}

function App() {
  return <profile />;
}

React는 <profile>을 사용자 컴포넌트가 아니라 알려지지 않은 HTML 태그로 해석합니다. Profile처럼 대문자로 시작해야 합니다.

17 React 애플리케이션의 시작점

일반적인 클라이언트 React 애플리케이션에는 React가 관리할 DOM 요소가 HTML에 하나 존재합니다.

<!-- index.html -->
<!doctype html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>React 애플리케이션</title>
  </head>
  <body>
    <div id="root"></div>
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

src/main.jsx에서는 createRoot로 React root를 만들고 root.render()로 최상위 컴포넌트를 렌더링합니다.

// src/main.jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";
import "./index.css";

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);

단계를 나누어 작성하면 다음과 같습니다.

const domNode = document.getElementById("root");
const root = createRoot(domNode);
root.render(<App />);
  1. document.getElementById("root")로 HTML의 DOM 요소를 찾습니다.
  2. createRoot(domNode)가 해당 DOM 요소를 React root로 만듭니다.
  3. root.render(<App />)가 App 컴포넌트를 root 안에 표시하도록 요청합니다.

React로 전체 애플리케이션을 만드는 경우 일반적으로 createRoot는 시작 시 한 번 호출합니다. 이후 화면 구성은 App 아래에 컴포넌트를 중첩해 확장합니다. React 공식 API: createRoot

17.1 root 요소를 찾지 못하는 오류

HTML의 id와 JavaScript 선택자가 다르면 null이 반환됩니다.

<div id="app"></div>
// root라는 id가 없으므로 null
const root = createRoot(document.getElementById("root"));

개발 단계에서 명시적으로 검사할 수 있습니다.

const domNode = document.getElementById("root");

if (!domNode) {
  throw new Error("#root 요소를 찾을 수 없습니다.");
}

createRoot(domNode).render(<App />);

18 렌더링과 커밋

React 공식 문서는 화면이 표시되는 과정을 세 단계로 설명합니다.

  1. 렌더링 촉발(trigger)
  2. 컴포넌트 렌더링(render)
  3. DOM에 커밋(commit)

React 공식 문서: Render and Commit

18.1 렌더링 촉발

컴포넌트 렌더링은 처음 애플리케이션이 시작되는 초기 렌더링과 이후 상태 업데이트에 의해 촉발됩니다. 3주차에는 root.render(<App />)가 초기 렌더링을 시작한다는 점을 이해합니다. 상태 업데이트는 5주차에 자세히 다룹니다.

18.2 컴포넌트 렌더링

React에서 렌더링은 컴포넌트 함수를 호출하여 화면에 무엇을 표시할지 계산하는 과정입니다.

function App() {
  return (
    <main>
      <Header />
      <Profile />
    </main>
  );
}

React는 App을 호출하고 App이 반환한 구조 안에서 Header와 Profile을 발견합니다. 이어서 각 컴포넌트를 호출하며 더 이상 사용자 컴포넌트가 남지 않을 때까지 재귀적으로 UI 구조를 계산합니다.

렌더링은 “화면에 픽셀을 그리는 행위”와 동일하지 않습니다. 렌더링 단계는 다음 UI가 어떤 모습이어야 하는지 계산하는 단계입니다.

18.3 DOM에 커밋

렌더링 계산이 끝나면 React는 필요한 변경을 실제 DOM에 반영합니다.

  • 초기 렌더링에서는 필요한 DOM 노드를 만들어 root에 추가합니다.
  • 다시 렌더링할 때는 이전 결과와 새 결과를 비교하고 실제로 달라진 최소한의 DOM 변경을 적용합니다.

다시 렌더링되었다고 모든 DOM 노드를 무조건 새로 만드는 것은 아닙니다. 렌더링은 UI 계산이고, commit은 계산 결과에 따라 DOM을 변경하는 별도 단계입니다.

18.4 브라우저 페인트

React가 DOM을 변경한 뒤 브라우저가 레이아웃과 페인트 과정을 수행해 사용자가 화면을 보게 됩니다. React의 render와 브라우저의 paint는 다른 개념입니다.

렌더링 요청
    ↓
컴포넌트 호출과 JSX 계산
    ↓
필요한 DOM 변경 커밋
    ↓
브라우저 레이아웃과 페인트

19 렌더링은 순수해야 한다

React는 컴포넌트를 순수 함수처럼 작성할 것을 요구합니다. 같은 입력을 받으면 같은 JSX를 반환하고, 렌더링 중 컴포넌트 밖의 값이나 기존 객체를 변경하지 않아야 합니다. React 공식 문서: Keeping Components Pure

다음 코드는 렌더링할 때마다 외부 변수를 변경합니다.

let count = 0;

function CounterLabel() {
  count += 1;
  return <p>렌더링 횟수: {count}</p>;
}

같은 입력에서도 호출 순서와 횟수에 따라 결과가 달라지므로 순수하지 않습니다.

지역 변수로 계산한 값은 안전합니다.

function Progress() {
  const completed = 3;
  const total = 15;
  const percentage = Math.round((completed / total) * 100);

  return <p>진행률: {percentage}%</p>;
}

렌더링 중에 DOM을 직접 변경하거나 네트워크 요청을 보내거나 외부 변수를 수정하면 안 됩니다. 사용자 행동에 따른 변경은 이벤트 처리기에서, 외부 시스템과의 동기화는 필요한 경우 Effect에서 수행합니다. 이벤트와 Effect는 이후 주차에 다룹니다.

19.1 StrictMode와 개발 중 이중 호출

개발 모드의 StrictMode는 순수하지 않은 코드를 발견하는 데 도움을 주기 위해 컴포넌트 함수를 추가로 호출할 수 있습니다.

createRoot(document.getElementById("root")).render(
  <StrictMode>
    <App />
  </StrictMode>
);

콘솔 출력이 두 번 보인다고 바로 React 오류로 판단하지 않습니다. 컴포넌트가 여러 번 호출되어도 결과가 올바르도록 순수하게 작성해야 합니다. StrictMode의 추가 검사는 개발 환경에서 동작하며 일반적인 프로덕션 화면에 그대로 적용되는 것은 아닙니다.

20 접근성을 고려한 JSX

JSX에서도 1주차에 배운 시맨틱 HTML과 접근성 원칙을 그대로 적용합니다.

function ProjectCard() {
  return (
    <article aria-labelledby="project-title">
      <h2 id="project-title">학습 기록 서비스</h2>
      <img
        src="/images/project-preview.png"
        alt="날짜별 학습 기록이 카드로 정렬된 서비스 화면"
      />
      <p>매일 학습한 내용을 기록하고 진행 상태를 확인합니다.</p>
      <a href="https://github.com/example/project">
        학습 기록 서비스 소스 코드 보기
      </a>
    </article>
  );
}
  • 의미 없는 div보다 main, section, article, nav 등 적절한 요소를 선택합니다.
  • 제목 단계를 논리적으로 유지합니다.
  • 정보성 이미지에는 목적을 설명하는 alt를 작성합니다.
  • 링크 텍스트만 읽어도 목적지를 이해할 수 있게 합니다.
  • className과 htmlFor를 정확히 사용합니다.
  • aria-* 속성은 소문자와 하이픈 형식을 유지합니다.
  • 클릭 동작을 위해 div에 이벤트를 붙이기보다 기본 button이나 a를 사용합니다.

21 포트폴리오 마크업을 JSX로 변환하기

21.1 JSX 기능은 웹사이트의 어디에 사용되는가

JSX 문법을 개별 규칙으로만 외우면 실제 화면을 만들 때 어떤 문법을 선택해야 할지 연결하기 어렵습니다. 다음 표는 이번 장의 기능이 일반적인 웹사이트 영역에서 어떻게 사용되는지를 보여줍니다.

JSX 기능 만들 수 있는 웹사이트 영역 적용 예
시맨틱 태그와 JSX 중첩 전체 페이지 구조 header, nav, main, section, footer 구성
className 모든 디자인 대상 내비게이션, Hero, 카드, 버튼에 CSS class 연결
중괄호 {} 데이터가 바뀌는 텍스트 사용자 이름, 프로젝트 제목, 상태, 날짜, 통계
속성의 JavaScript 표현식 이미지와 링크 프로필 이미지 URL, 프로젝트 저장소 주소, 대체 텍스트
Fragment 불필요한 wrapper가 없어야 하는 영역 페이지의 main과 footer를 나란한 최상위 형제로 반환
style 객체 데이터에 따라 즉시 바뀌는 제한적 표현 진행률 너비, 상태 색상 등 동적 값
함수 컴포넌트 반복되거나 독립적인 UI 영역 Header, Hero, ProjectCard, Contact, Footer
createRoot와 root.render React 웹사이트 시작점 App 전체를 #root에 연결
순수한 렌더링 데이터 기반 화면 전체 같은 프로젝트 데이터로 항상 같은 카드 출력

예를 들어 회사 소개 사이트에서는 JSX 중첩으로 페이지 구조를 만들고, 중괄호로 회사명과 실적 데이터를 표시하며, 이미지의 src에 데이터 값을 연결할 수 있습니다. 쇼핑몰에서는 상품명, 가격, 할인 상태와 이미지 주소를 JSX 표현식으로 출력합니다. 대시보드에서는 사용자 이름, 통계 수치와 업데이트 시간을 표시합니다. 이번 수업의 포트폴리오에서는 자기소개, 기술 목록, 프로젝트 카드와 연락처 영역에 같은 원리를 적용합니다.

21.2 Header와 내비게이션 만들기

Header는 로고 또는 사이트 이름과 주요 이동 링크를 포함합니다. JSX에서는 HTML의 시맨틱 구조를 유지하면서 className으로 2주차 CSS를 연결합니다.

function SiteHeader() {
  const siteName = "홍길동.dev";

  return (
    <header className="site-header">
      <a className="site-logo" href="#top">
        {siteName}
      </a>

      <nav aria-label="주요 메뉴">
        <ul className="navigation-list">
          <li><a href="#about">소개</a></li>
          <li><a href="#skills">기술</a></li>
          <li><a href="#projects">프로젝트</a></li>
          <li><a href="#contact">연락처</a></li>
        </ul>
      </nav>
    </header>
  );
}

이 예제에서 {siteName}은 사이트 이름을 데이터로 관리합니다. 사이트명을 변경할 때 JSX 안의 여러 문장을 찾을 필요 없이 변수값을 바꿀 수 있습니다. nav와 aria-label은 보조 기술이 내비게이션의 역할을 이해하도록 돕습니다. className은 CSS의 .site-header, .site-logo, .navigation-list와 연결됩니다.

21.3 Hero 영역 만들기

Hero는 첫 화면에서 개발자의 정체성과 핵심 메시지를 전달하는 영역입니다. JSX 중괄호와 동적 속성을 함께 사용하기 좋은 부분입니다.

function Hero() {
  const developer = {
    name: "홍길동",
    role: "프론트엔드 개발자",
    message: "사용하기 쉽고 접근 가능한 웹 인터페이스를 만듭니다.",
    profileImage: "/images/profile.jpg",
  };

  return (
    <section className="hero" id="about" aria-labelledby="hero-title">
      <div className="hero__content">
        <p className="hero__role">{developer.role}</p>
        <h1 id="hero-title">안녕하세요, {developer.name}입니다.</h1>
        <p className="hero__message">{developer.message}</p>
        <a className="button-link" href="#projects">
          프로젝트 살펴보기
        </a>
      </div>

      <img
        className="hero__image"
        src={developer.profileImage}
        alt={`${developer.name}의 프로필`}
        width={480}
        height={480}
      />
    </section>
  );
}

여기서는 객체 속성을 텍스트와 이미지 속성에 연결했습니다. src={developer.profileImage}는 이미지 경로를, 템플릿 리터럴이 포함된 alt는 개발자 이름에 맞는 대체 텍스트를 만듭니다. 같은 구조를 유지하면서 객체값만 바꾸면 다른 학생의 Hero 영역으로 재사용할 수 있습니다.

21.4 기술 소개 영역 만들기

3주차에는 리스트 반복 렌더링보다 JSX 구조 자체에 집중하기 위해 기술 항목을 직접 작성합니다. 배열의 map()을 이용한 목록 렌더링과 key는 7주차에서 다룹니다.

function Skills() {
  return (
    <section className="skills" id="skills" aria-labelledby="skills-title">
      <h2 id="skills-title">사용 기술</h2>
      <ul className="skills__list">
        <li className="skills__item">HTML</li>
        <li className="skills__item">CSS</li>
        <li className="skills__item">JavaScript</li>
        <li className="skills__item">React</li>
      </ul>
    </section>
  );
}

이 구조는 개발자 포트폴리오의 기술 배지, 회사 사이트의 서비스 목록, 쇼핑몰의 상품 특징과 대시보드의 주요 기능 안내 영역으로 바꾸어 사용할 수 있습니다.

21.5 프로젝트 카드 만들기

프로젝트 카드는 제목, 상태, 설명, 사용 기술, 실행 링크와 소스 코드 링크를 묶는 독립적인 콘텐츠입니다. 따라서 article이 적합합니다.

function ProjectCard() {
  const project = {
    title: "학습 기록 서비스",
    status: "개발 중",
    description: "날짜별 학습 내용과 진행 상태를 기록하는 웹 서비스입니다.",
    imageUrl: "/images/learning-log.png",
    demoUrl: "https://example.com/learning-log",
    repositoryUrl: "https://github.com/example/learning-log",
  };

  return (
    <article className="project-card">
      <img
        className="project-card__image"
        src={project.imageUrl}
        alt={`${project.title}의 실행 화면`}
      />

      <div className="project-card__content">
        <p className="project-card__status">{project.status}</p>
        <h3>{project.title}</h3>
        <p>{project.description}</p>

        <div className="project-card__links">
          <a href={project.demoUrl}>실행 화면 보기</a>
          <a href={project.repositoryUrl}>소스 코드 보기</a>
        </div>
      </div>
    </article>
  );
}

중괄호가 실제 웹사이트 데이터와 화면을 연결합니다. 프로젝트가 바뀌어도 마크업 구조를 다시 작성하지 않고 project 객체의 값을 교체할 수 있습니다. 이 방식은 쇼핑몰의 상품 카드, 여행 사이트의 장소 카드, 영화 사이트의 콘텐츠 카드에도 동일하게 적용됩니다. 다음 주 Props를 배우면 ProjectCard 바깥에서 데이터를 전달하여 같은 카드 구조를 여러 프로젝트에 재사용할 수 있습니다.

21.6 연락처와 Footer 만들기

function Contact() {
  const email = "student@example.com";
  const githubUrl = "https://github.com/example";

  return (
    <section className="contact" id="contact" aria-labelledby="contact-title">
      <h2 id="contact-title">연락처</h2>
      <address>
        <a href={`mailto:${email}`}>{email}</a>
        <a href={githubUrl}>GitHub 프로필</a>
      </address>
    </section>
  );

function SiteFooter() {
  const owner = "홍길동";
  const year = 2026;

  return (
    <footer className="site-footer">
      <small>&copy; {year} {owner}. All rights reserved.</small>
    </footer>

href={mailto:${email}}은 템플릿 리터럴로 이메일 링크를 생성합니다. Footer에서는 연도와 소유자 이름을 표현식으로 출력합니다. 블로그, 회사 사이트와 쇼핑몰에서도 사업자 정보, 저작권, 정책 링크를 구성할 때 같은 JSX 구조를 사용할 수 있습니다.

21.7 웹사이트 영역을 App에서 조립하기

각 영역을 함수 컴포넌트로 작성한 뒤 App에서 실제 페이지 순서대로 조립합니다.

export default function App() {
  return (
    <>
      <SiteHeader />
      <main id="top">
        <Hero />
        <Skills />
        <section id="projects" aria-labelledby="projects-title">
          <h2 id="projects-title">프로젝트</h2>
          <ProjectCard />
        </section>
        <Contact />
      </main>
      <SiteFooter />
    </>
  );
}

이 코드는 JSX가 단순히 작은 태그를 작성하는 문법이 아니라 웹사이트 전체 구조를 표현하는 조립 언어로 사용된다는 점을 보여줍니다. App은 페이지의 큰 틀을 보여주고 각 컴포넌트는 하나의 명확한 화면 영역을 담당합니다. 4주차에는 각 컴포넌트를 별도 파일로 분리하고 Props로 데이터를 전달하여 재사용 가능한 구조로 발전시킵니다.

1주차 HTML의 일부를 JSX로 옮겨 살펴봅시다.

<!-- 기존 HTML -->
<section class="profile" id="about">
  <img
    class="profile__image"
    src="images/profile.jpg"

</section>

import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";
import "./index.css";

const domNode = document.getElementById("root");

if (!domNode) {
  throw new Error("#root 요소가 필요합니다.");

createRoot(domNode).render(
  <StrictMode>
    <App />
  </StrictMode>
);

이 예제에서 확인할 수 있는 내용은 다음과 같습니다.

  • 컴포넌트 이름은 대문자로 시작합니다.
  • 컴포넌트는 JSX를 반환합니다.
  • class 대신 className을 사용합니다.
  • 빈 요소는 />로 닫습니다.
  • 중괄호로 문자열, 숫자, 객체 속성과 템플릿 리터럴을 사용합니다.
  • Fragment로 여러 최상위 요소를 그룹화합니다.
  • createRoot와 root.render가 초기 렌더링을 시작합니다.
  • 시맨틱 HTML과 접근성 속성을 JSX에서도 유지합니다.

JSX로 Header, Hero, 기술 목록, 프로젝트 미리보기와 Footer를 React 엘리먼트로 기술할 수 있습니다. 화면에 보이는 결과는 HTML과 비슷하지만, 표시할 값을 JavaScript에서 계산하고 React가 DOM에 반영한다는 점이 다릅니다.

24 자주 발생하는 오류

24.1 Adjacent JSX elements 오류

return (
  <h1>제목</h1>
  <p>설명</p>
);

형제 요소를 하나의 부모 또는 Fragment로 감쌉니다.

return (
  <>
    <h1>제목</h1>
    <p>설명</p>
  </>
);

24.2 Expected corresponding JSX closing tag 오류

시작 태그와 종료 태그 이름 또는 중첩 순서가 맞지 않을 때 발생합니다.

<section>
  <p>내용</p>
</section>

24.3 class 관련 경고

<div class="card">...</div>

JSX에서는 className을 사용합니다.

<div className="card">...</div>

24.4 Objects are not valid as a React child

객체 전체를 렌더링하려 했을 가능성이 큽니다.

const project = { title: "포트폴리오" };

// 잘못된 예
<p>{project}</p>

// 올바른 예
<p>{project.title}</p>

24.5 Target container is not a DOM element

createRoot에 null이 전달된 경우입니다. index.html의 id와 getElementById 문자열이 일치하는지 확인합니다.

<div id="root"></div>
createRoot(document.getElementById("root")).render(<App />);

24.6 함수가 화면에 표시되지 않음

함수를 호출하지 않고 함수 자체를 중괄호에 넣은 경우입니다.

function getTitle() {
  return "프로젝트";
}

<h1>{getTitle}</h1>   // 함수 자체
<h1>{getTitle()}</h1> // 함수 호출 결과

24.7 중괄호를 따옴표 안에 작성함

<img src="{imageUrl}" alt="{description}" />

이 코드는 변수값이 아닌 중괄호 문자를 포함한 문자열입니다.

<img src={imageUrl} alt={description} />

24.8 return 뒤에 줄바꿈함

function App() {
  return
    <h1>제목</h1>;
}

return과 여는 괄호를 같은 줄에 둡니다.

function App() {
  return (
    <h1>제목</h1>
  );
}

25 JSX와 렌더링 점검

코드가 예상대로 동작하지 않을 때 다음 순서로 확인합니다.

  1. 브라우저 Console의 첫 번째 오류와 파일·줄 번호를 읽습니다.
  2. JSX가 하나의 루트 요소 또는 Fragment로 감싸졌는지 확인합니다.
  3. 모든 태그가 닫혔고 올바르게 중첩되었는지 확인합니다.
  4. className, htmlFor, camelCase 속성을 사용했는지 확인합니다.
  5. 고정 문자열은 따옴표, JavaScript 표현식은 중괄호인지 확인합니다.
  6. 객체 전체가 아니라 렌더링할 속성을 선택했는지 확인합니다.
  7. 컴포넌트 이름이 대문자로 시작하는지 확인합니다.
  8. index.html에 root DOM 요소가 있는지 확인합니다.
  9. createRoot가 올바른 DOM 요소를 받는지 확인합니다.
  10. 렌더링 중 외부 값을 변경하는 코드가 없는지 확인합니다.
