7  6주차: React Hook 기초

Hook은 함수 컴포넌트가 React의 기능을 사용할 수 있게 하는 특별한 함수입니다. 5주차에서 사용한 useState도 Hook이며, 이번 장에서는 Hook의 공통 규칙을 정리한 뒤 useEffect로 외부 시스템과 동기화하고 useRef로 DOM 요소나 렌더링과 무관한 값을 참조하는 방법을 다룹니다. 마지막에는 여러 컴포넌트에서 반복되는 상태 기반 로직을 사용자 정의 Hook으로 추출합니다.

8 Hook의 역할

React 컴포넌트는 Props를 받아 JSX를 반환하는 순수한 렌더링 함수를 기본으로 합니다. 그러나 실제 웹사이트는 렌더링 사이에 값을 기억하고, 브라우저 API와 연결하며, DOM 요소에 접근해야 합니다. Hook은 이러한 React 기능을 함수 컴포넌트에 연결합니다.

import { useState } from "react";

function LikeButton() {
  const [likes, setLikes] = useState(0);
  return (
    <button onClick={() => setLikes((count) => count + 1)}>
      좋아요 {likes}
    </button>
  );
}

Hook은 일반 함수처럼 보이지만 React가 호출 순서를 이용해 각 Hook의 State와 Effect를 구분합니다. 따라서 호출 위치에 규칙이 있습니다.

9 Hook 호출 규칙

Hook은 다음 두 위치에서만 호출합니다.

  1. 함수 컴포넌트의 최상위 수준
  2. 사용자 정의 Hook의 최상위 수준

반복문, 조건문, 중첩 함수, 이벤트 처리기나 try 블록 안에서 호출하면 안 됩니다. 컴포넌트가 렌더링될 때마다 Hook이 동일한 순서로 호출되어야 React가 이전 렌더링의 값과 정확히 연결할 수 있기 때문입니다.

function Profile() {
  const [isOpen, setIsOpen] = useState(false);
  const [name, setName] = useState("");

  return <p>{name || "이름 미입력"}</p>;
}
function Profile({ canEdit }) {
  // 잘못된 예: canEdit 값에 따라 Hook 호출 여부가 달라진다.
  if (canEdit) {
    const [name, setName] = useState("");
  }

  return <p>프로필</p>;
}

조건에 따라 동작을 바꾸고 싶다면 Hook 자체는 항상 호출하고 Hook 내부 또는 렌더링 결과에서 조건을 처리합니다.

function Profile({ canEdit }) {
  const [name, setName] = useState("");

  if (!canEdit) {
    return <p>{name || "공개 사용자"}</p>;
  }

  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}

10 렌더링, 이벤트와 Effect 구분

컴포넌트 안의 코드는 역할에 따라 세 종류로 나눌 수 있습니다.

종류 실행 시점 역할 예시
렌더링 로직 React가 컴포넌트를 호출할 때 Props와 State로 JSX 계산 검색 결과 목록 계산
이벤트 처리기 사용자가 특정 행동을 했을 때 그 행동에 따른 변경 수행 제출, 저장, 삭제
Effect 렌더링이 화면에 반영된 뒤 외부 시스템과 동기화 문서 제목, 타이머, DOM API

렌더링 중 계산할 수 있는 값은 Effect에 넣지 않습니다. 사용자 클릭 때문에 실행되어야 하는 작업은 이벤트 처리기에 둡니다. Effect는 특정 클릭이 아니라 화면에 렌더링된 상태 자체 때문에 외부 시스템을 맞춰야 할 때 사용합니다.

function Profile({ firstName, lastName }) {
  // Effect가 필요 없다. 렌더링 중 바로 계산한다.
  const fullName = `${lastName}${firstName}`;
  return <h1>{fullName}</h1>;
}

11 useEffect로 외부 시스템과 동기화하기

useEffect(setup, dependencies)는 렌더링 결과가 DOM에 반영된 후 setup 함수를 실행합니다. 브라우저 문서 제목은 React가 직접 관리하는 JSX 밖의 시스템이므로 Effect 사용이 적절합니다.

import { useEffect, useState } from "react";

function ProjectSearch() {
  const [query, setQuery] = useState("");

  useEffect(() => {
    document.title = query
      ? `${query} 검색 · 포트폴리오`
      : "포트폴리오";
  }, [query]);

  return (
    <label>
      프로젝트 검색
      <input value={query} onChange={(e) => setQuery(e.target.value)} />
    </label>
  );
}

첫 렌더링 뒤 문서 제목을 설정하고, 이후 query가 바뀐 렌더링이 커밋될 때 다시 동기화합니다. 포트폴리오 검색어, 현재 보고 있는 프로젝트 이름 또는 읽지 않은 알림 수를 브라우저 탭 제목에 반영할 때 사용할 수 있습니다.

11.1 의존성 배열의 의미

Effect가 읽는 컴포넌트 내부의 Props, State와 변수는 반응형 값입니다. 의존성 배열에는 Effect가 사용하는 모든 반응형 값을 포함해야 합니다. React는 이전 배열과 새 배열의 각 값을 Object.is로 비교해 다시 동기화할지 결정합니다.

function ProjectPage({ projectTitle }) {
  useEffect(() => {
    document.title = `${projectTitle} · 포트폴리오`;
  }, [projectTitle]);

  return <h1>{projectTitle}</h1>;
}

의존성 배열을 생략하면 모든 렌더링 뒤 실행되고, 빈 배열 []은 컴포넌트가 화면에 처음 추가된 뒤 실행되는 동기화를 나타냅니다. 빈 배열은 “한 번만 실행하는 문법”으로 외우기보다 Effect가 반응형 값을 읽지 않는다는 의미로 이해합니다.

function VisitMessage() {
  useEffect(() => {
    console.log("방문 안내가 화면에 연결되었습니다.");
  }, []);

  return <p>포트폴리오에 방문해 주셔서 감사합니다.</p>;
}

의존성 경고를 없애려고 값을 임의로 빼거나 린터를 비활성화하면 오래된 값을 읽는 버그가 발생합니다. Effect가 너무 자주 실행된다면 의존성을 숨기기보다 Effect의 책임을 줄이고 렌더링 또는 이벤트 처리기로 옮길 로직이 없는지 확인합니다.

12 정리 함수와 Effect 생명주기

Effect는 동기화를 시작하고 필요할 때 중단합니다. setup 함수가 cleanup 함수를 반환하면 React는 다음 Effect를 실행하기 전과 컴포넌트가 화면에서 제거될 때 cleanup을 호출합니다.

import { useEffect, useState } from "react";

function Clock() {
  const [now, setNow] = useState(() => new Date());

  useEffect(() => {
    const timerId = setInterval(() => {
      setNow(new Date());
    }, 1000);

    return () => clearInterval(timerId);
  }, []);

  return <time dateTime={now.toISOString()}>{now.toLocaleTimeString("ko-KR")}</time>;
}

이 코드는 포트폴리오의 현재 시간, 프로젝트 시연의 경과 시간이나 자동 갱신 상태에 활용할 수 있습니다. 정리 함수가 없으면 컴포넌트가 사라진 뒤에도 타이머가 남거나 다시 마운트할 때 타이머가 중복될 수 있습니다.

12.1 브라우저 이벤트 구독 정리

브라우저 이벤트를 등록했다면 같은 처리기 참조로 해제합니다.

function WindowWidth() {
  const [width, setWidth] = useState(() => window.innerWidth);

  useEffect(() => {
    function handleResize() {
      setWidth(window.innerWidth);
    }

    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return <p>현재 화면 너비: {width}px</p>;
}

반응형 레이아웃 자체는 2주차에서 배운 CSS 미디어 쿼리를 우선합니다. JavaScript에서 실제 너비 값이 필요한 차트, 캔버스 또는 복잡한 위젯에만 이 패턴을 사용합니다.

13 개발 환경에서 Effect가 두 번 실행되는 이유

Strict Mode를 사용하는 개발 환경에서는 React가 컴포넌트를 마운트하고 정리한 뒤 다시 마운트하여 Effect 구현을 점검할 수 있습니다. 이는 제품 환경의 동작이 아니라 정리 함수 누락을 발견하기 위한 검사입니다. “두 번 실행을 막는 플래그”를 추가하기보다 setup과 cleanup이 대칭인지 확인합니다.

useEffect(() => {
  window.addEventListener("resize", handleResize);
  return () => window.removeEventListener("resize", handleResize);
}, []);

연결했다면 연결을 해제하고, 타이머를 만들었다면 제거하며, 외부 위젯을 시작했다면 종료합니다. 이렇게 작성하면 setup → cleanup → setup 순서에서도 사용자에게는 한 번 연결된 것과 같은 결과가 보입니다.

14 Effect가 필요하지 않은 경우

Effect를 State A의 변경을 감지해 State B를 갱신하는 용도로 사용하면 불필요한 렌더링이 추가되고 두 값이 어긋날 수 있습니다.

function Name({ firstName, lastName }) {
  const [fullName, setFullName] = useState("");

  // 불필요한 Effect
  useEffect(() => {
    setFullName(`${lastName}${firstName}`);
  }, [firstName, lastName]);

  return <p>{fullName}</p>;
}
function Name({ firstName, lastName }) {
  const fullName = `${lastName}${firstName}`;
  return <p>{fullName}</p>;
}

또한 폼 제출이나 구매처럼 특정 사용자 행동 때문에 실행되는 코드는 Effect가 아니라 이벤트 처리기에 둡니다.

function ContactForm() {
  function handleSubmit(event) {
    event.preventDefault();
    alert("문의가 저장되었습니다.");
  }

  return <form onSubmit={handleSubmit}><button>문의 저장</button></form>;
}

15 useRef: 렌더링과 무관한 값 기억하기

useRef(initialValue)는 { current: initialValue } 형태의 객체를 반환하며 같은 컴포넌트 인스턴스의 렌더링 사이에서 동일한 객체를 유지합니다. ref.current를 변경해도 재렌더링되지 않습니다. 따라서 화면을 결정하는 값은 State에 두고, 렌더링에 사용하지 않는 타이머 ID나 DOM 참조를 Ref에 둡니다.

import { useRef } from "react";

function SearchBox() {
  const inputRef = useRef(null);

  function handleFocus() {
    inputRef.current?.focus();
  }

  return (
    <section>
      <label htmlFor="project-search">프로젝트 검색</label>
      <input ref={inputRef} id="project-search" />
      <button type="button" onClick={handleFocus}>검색창으로 이동</button>
    </section>
  );
}

React는 input DOM 노드가 생성되면 inputRef.current에 그 노드를 넣습니다. 이 기능은 검색 버튼에서 입력창으로 포커스를 이동하거나, 대화상자가 열릴 때 적절한 요소에 포커스를 설정하고, 미디어 요소를 제어할 때 사용합니다. 포커스를 이동할 때는 키보드 사용자가 현재 위치를 예측할 수 있도록 명확한 사용자 행동에 연결합니다.

15.1 Ref와 State 선택 기준

function RenderCountExample() {
  const renderCount = useRef(0);
  renderCount.current += 1;
  return <p>Ref 변경은 화면 갱신을 요청하지 않습니다.</p>;
}

다음 질문으로 선택할 수 있습니다.

  • 값이 바뀌면 화면도 바뀌어야 하는가? → State
  • 렌더링과 무관하게 값이나 DOM 노드를 기억하는가? → Ref
  • Props와 State에서 바로 계산할 수 있는가? → 지역 변수

렌더링 중 ref.current를 읽거나 쓰는 코드는 예측하기 어렵습니다. DOM 접근은 이벤트 처리기 또는 필요한 Effect에서 수행합니다.

16 사용자 정의 Hook

둘 이상의 컴포넌트에서 같은 상태 기반 로직이 반복되면 use로 시작하는 함수로 추출할 수 있습니다. 사용자 정의 Hook은 로직을 공유하지만 각 호출의 State는 독립적입니다.

import { useEffect } from "react";

function useDocumentTitle(title) {
  useEffect(() => {
    const previousTitle = document.title;
    document.title = title;

    return () => {
      document.title = previousTitle;
    };
  }, [title]);
}
function ProjectPage({ project }) {
  useDocumentTitle(`${project.title} · 포트폴리오`);
  return <h1>{project.title}</h1>;
}

컴포넌트는 “프로젝트 제목을 문서 제목으로 사용한다”는 의도만 드러내고 브라우저 동기화 세부 구현은 Hook에 맡깁니다. 사용자 정의 Hook 이름은 useDocumentTitle, useOnlineStatus, useWindowWidth처럼 목적이 드러나야 합니다.

16.1 사용자 정의 Hook은 State를 공유하지 않는다

function useToggle(initialValue = false) {
  const [isOpen, setIsOpen] = useState(initialValue);
  const toggle = () => setIsOpen((open) => !open);
  return [isOpen, toggle];
}

function Portfolio() {
  const [isBioOpen, toggleBio] = useToggle(false);
  const [isMenuOpen, toggleMenu] = useToggle(false);

  return (
    <main>
      <button onClick={toggleBio}>자기소개 {isBioOpen ? "닫기" : "열기"}</button>
      <button onClick={toggleMenu}>메뉴 {isMenuOpen ? "닫기" : "열기"}</button>
    </main>
  );
}

두 호출은 같은 구현을 사용하지만 서로 다른 State를 가집니다. 실제 값을 공유하려면 공통 부모 State나 이후 학습할 Context 같은 데이터 공유 구조가 필요합니다.

17 종합 예제: Hook으로 포트폴리오와 브라우저 연결하기

import { useEffect, useRef, useState } from "react";

function useDocumentTitle(title) {
  useEffect(() => {
    const previousTitle = document.title;
    document.title = title;
    return () => { document.title = previousTitle; };
  }, [title]);
}

function Clock() {
  const [now, setNow] = useState(() => new Date());

  useEffect(() => {
    const timerId = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(timerId);
  }, []);

  return <time dateTime={now.toISOString()}>{now.toLocaleTimeString("ko-KR")}</time>;
}

export default function PortfolioTools() {
  const [query, setQuery] = useState("");
  const searchRef = useRef(null);
  useDocumentTitle(query ? `${query} 검색 · 포트폴리오` : "포트폴리오");

  return (
    <main>
      <header><h1>홍길동 포트폴리오</h1><Clock /></header>
      <section>
        <label htmlFor="search">프로젝트 검색</label>
        <input
          ref={searchRef}
          id="search"
          value={query}
          onChange={(event) => setQuery(event.target.value)}
        />
        <button type="button" onClick={() => searchRef.current?.focus()}>
          검색창 포커스
        </button>
      </section>
    </main>
  );
}

이 예제에서 State는 검색어와 시간을 화면에 표현하고, Effect는 문서 제목과 타이머라는 외부 시스템을 동기화하며, Ref는 DOM 입력 요소를 가리킵니다. 각 Hook의 역할이 겹치지 않도록 구분하는 것이 핵심입니다.

18 실행 결과: Hook으로 확장한 포트폴리오

검색어를 입력하면 브라우저 탭 제목이 바뀌고, 포커스 버튼은 검색창으로 키보드 포커스를 이동합니다. 시계는 Effect로 생성한 타이머에 따라 갱신되며 테마 버튼은 React State와 문서 속성의 동기화를 보여줍니다.

19 자주 발생하는 오류

19.1 조건문 안에서 Hook 호출

Hook 호출 순서가 렌더링마다 달라집니다. Hook은 최상위에서 호출하고 조건은 Hook 내부 또는 JSX에서 처리합니다.

19.2 모든 계산을 Effect로 처리

Props와 State에서 계산 가능한 값은 렌더링 중 계산합니다. Effect 안에서 다시 State를 갱신하면 불필요한 렌더링이 생깁니다.

19.3 의존성 경고 무시

Effect가 읽는 반응형 값을 배열에서 제외하면 최신 값과 동기화되지 않습니다. 린터 주석으로 경고를 숨기지 말고 Effect 구조를 수정합니다.

19.4 정리 함수 누락

이벤트 구독, 타이머와 외부 연결에는 대응하는 해제 작업이 필요합니다. setup과 cleanup을 한 쌍으로 읽습니다.

19.5 화면에 표시할 값을 Ref에 저장

Ref 변경은 재렌더링을 요청하지 않습니다. 사용자에게 보여야 하는 값은 State로 관리합니다.

19.6 사용자 정의 Hook을 단순 함수처럼 호출

사용자 정의 Hook도 Hook 규칙을 따릅니다. 이벤트 처리기나 조건문에서 호출하지 않으며 이름을 use로 시작해 린터와 개발자가 Hook임을 알 수 있게 합니다.
